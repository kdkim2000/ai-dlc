## 공통 설계 원칙

모든 10개 스킬이 공유하는 규칙 (`ai-dlc-common/references/output-policy.md`에 전문 기재):

1. **파일명 규칙**: `{산출물유형}_{사업명}_{YYYYMMDD}.md` — OS 금지 문자/공백 → `_`
2. **출력 모드**: 기본 파일 생성; `"보여만 줘"/"파일 만들지 마"/"여기에 출력"` 키워드 시 대화창 출력
3. **버전 이력**: 모든 산출물 하단에 `| 버전 | 일자 | 작성자 | 변경 내용 |` 표 포함
4. **수정 스킬(revise)**: 버전 +0.1, 새 파일명에 `_v{버전}` 추가
5. **추측 표시**: `<!-- TODO: 확인 필요 -->` 인라인 주석
6. **언어**: 한국어 고정, 기술 고유명사 원문 유지
7. **GFM 표**: `:---` 정렬 명시
8. **기존 파일 존재 시**: 덮어쓰기 전 사용자 확인

## 산출물 표준 포맷

### 서비스 카탈로그 (SC)
```
| SC-ID | 서비스명 | 카테고리 | 연관 요구사항 ID | 설명 | 우선순위 |
```
- SC-NNN 채번; 카테고리: 사용자관리/주문·배송/결제/알림/콘텐츠/인프라/기타

### 기능 요구사항 심화 (FR 심화)
```
| FR-ID | 기능명 | 서비스(SC-ID) | 액터 | 설명 | 사전조건 | 사후조건 | 예외 흐름 | 우선순위 |
```
- 기존 ai-dlc-requirements 대비 액터·사전/사후조건·예외 흐름 추가

### 비기능 요구사항 심화 (NFR 심화)
```
| ID | 분류 | 요구사항명 | 측정지표 | 목표값(단위) | 검증방법 | 우선순위 |
```
- 기존 ai-dlc-requirements 대비 검증방법 컬럼 추가, 측정 단위 강제

### 비즈니스 규칙 (BR)
```
| BR-ID | 규칙명 | 도메인 | 조건 (When/If) | 행동 (Then) | 우선순위 | 상태 |
```
- BR-NNN 채번; 상태: 초안/검증중/확정/폐기; 우선순위: 높음/중간/낮음

### 도메인 표준 용어 (TM)
```
| TM-ID | 용어 | 정의 | 도메인 | 동의어/유사어 | 사용 예시 | 출처 | 상태 |
```
- TM-NNN 채번; 상태: 초안/검토중/확정/폐기

### 검증 보고서 (validate 스킬 공통)
```
| 검증 항목 | 발견 건수 | 심각도 |
이슈 목록: | 이슈-ID(VI-NNN) | 대상 항목 | 이슈 유형 | 설명 | 권고 조치 |
이슈 유형: 모순/중복/모호/누락/형식오류
종합 판정: 승인 / 조건부 승인 / 재검토 필요
```

## 스킬별 핵심 설계

### 1. `ai-dlc-service-catalog`
- **트리거**: "서비스 분류", "서비스 카탈로그", "MSA 서비스 분리", "서비스 단위로 나눠줘"
- **핵심 로직**: FR 항목들을 비즈니스 기능 클러스터로 묶어 서비스명 부여
- **기본 가정**: MSA (입력에 "모놀리식" 언급 시 모듈 단위로 전환)
- **하나의 FR이 두 서비스에 걸치는 경우**: 주 서비스 배정 + 비고에 연계 표시

### 2. `ai-dlc-functional-req`
- **트리거**: "기능 요구사항 정의", "FR 작성", "유스케이스 정의", "기능 명세 작성"
- **기존 ai-dlc-requirements 대비**: 액터, 사전/사후조건, 예외 흐름 심화
- **입력**: 메모, 회의록, 기존 요구사항 정의서 모두 가능

### 3. `ai-dlc-nonfunctional-req`
- **트리거**: "비기능 요구사항 정의", "NFR 작성", "성능/보안/품질 요구사항 정의"
- **분류 체계**: `ai-dlc-requirements/references/id-codes.md`와 동일 (참조)
- **핵심 추가**: 측정 단위 강제화, 검증방법 컬럼
- **측정 불가 표현 처리**: "빠르게" → TODO 표시 후 수치화 요청

### 4. `ai-dlc-biz-rules-create`
- **트리거**: "비즈니스 규칙 생성", "BR 작성", "업무 규칙 정의", "비즈니스 규칙 뽑아줘"
- **추출 패턴**: `~해야 한다`, `~인 경우`, `~이면 ~한다`, `~금지`, `예외`, 순서/프로세스
- **클러스터링**: 유사 규칙을 도메인별로 묶어 정리

### 5. `ai-dlc-biz-rules-validate`
- **트리거**: "비즈니스 규칙 검증", "BR 검토", "규칙 충돌 확인"
- **검증 5항목**: 모순(높음) / 중복(중간) / 모호(중간) / 누락(중간) / 형식오류(낮음)
- **종합 판정**: 승인 / 조건부 승인 / 재검토 필요

### 6. `ai-dlc-biz-rules-revise`
- **트리거**: "비즈니스 규칙 수정", "BR 업데이트", "규칙 검증 반영"
- **입력**: 검증 보고서(VI-NNN 이슈) 또는 자연어 변경 지시
- **처리**: 이슈 반영 + 수정 행 `[v{버전} 수정]` 표시 + 버전 이력 갱신

### 7. `ai-dlc-glossary-create`
- **트리거**: "도메인 표준 용어 생성", "용어사전 만들어줘", "글로서리 작성"
- **추출 전략**: 명사형 도메인 키워드 → 동의어 통합 → 대표 용어 결정 → 정의 생성
- **정의 원칙**: 최소 1개 완전한 문장; 시스템 맥락 정의 (사전 정의 아님)

### 8. `ai-dlc-glossary-validate`
- **트리거**: "도메인 용어 검증", "용어사전 검토", "글로서리 검증"
- **검증 5항목**: 정의 모호성(높음) / 동의어 충돌(높음) / 도메인 불일치(중간) / 미사용 용어(낮음) / 형식오류(낮음)

### 9. `ai-dlc-glossary-revise`
- **트리거**: "도메인 용어 수정", "용어사전 업데이트", "용어 검증 반영"
- **패턴**: `ai-dlc-biz-rules-revise`와 동일 구조

### 10. `ai-dlc-glossary-apply`
- **트리거**: "표준 용어 반영", "용어 통일", "요구사항에 용어사전 적용", "용어 치환"
- **핵심 로직**: 확정 용어의 동의어/유사어를 요구사항 문서에서 탐색 → 대표 용어로 치환
- **치환 원칙**: 확정 용어만 적용 (초안 제외); 문맥 변경 위험 시 TODO 처리
- **치환 요약 리포트**: `| 원래 표현 | 대체 표준 용어 | 등장 횟수 | 처리 결과 |`
