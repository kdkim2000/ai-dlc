## Context

AI-DLC 파이프라인은 요구사항 → 분석 → 설계 → 개발 → 검증까지 완성된 스킬 체계를 갖추고 있으나,
**개발·검증 완료 후 최종 납품 패키지를 만드는 단계가 부재**했다.

현황:
- 40종 이상의 마크다운 산출물이 프로젝트 디렉터리에 분산
- `ai-dlc-md-to-word`로 개별 문서만 변환 가능
- 인수인계 받는 사람이 "어떤 문서가 있는지", "시스템이 무엇인지", "어떻게 쓰는지"를 파악할 단일 진입점 없음

**목표**: 납품 담당자·개발자·운영자·최종 사용자가 **문서만으로** 시스템 개발 내용과 사용법을 완전히 이해할 수 있는 납품 문서 세트 자동 생성.

---

## 사용자 요구사항

> "ai-dlc의 마지막 단계에서 어플리케이션 개발 및 검증을 완료된 이후 요구사항도출에서 분석 개발중 생성된 문서를 최종 건내주기 위해 필요한 skill을 계획한다. 문서만으로 개발 내용과 사용법을 충분히 확인가능 하도록 구성될 수 있도록 계획을 수립하고 시행하라."

## 전체 흐름

```
[개발 및 검증 완료]
         │
         ▼
ai-dlc-delivery-checklist   ← (1) "납품 검수 목록 만들어줘"
(납품검수목록_*.md)            모든 산출물 수집 + 필수 문서 누락 보고
         │
    ┌────┼────────────────┐
    ▼    ▼                ▼
  (2)  (3)              (4)
시스템개요서  사용자매뉴얼   개발자가이드
(모든 산출물 통합)  (화면설계서→UX)  (API+DB+소스구조)
    └────┴────────────────┘
                │
                ▼
    ai-dlc-delivery-package  ← (5) "납품 패키지 만들어줘"
    (납품패키지_인덱스_*.md)   최종 인덱스 + Word 변환 안내
```

## 설계 결정 사항

| 결정 | 내용 | 근거 |
|:---|:---|:---|
| 검수 → 납품 문서 → 패키지 순서 | 검수 먼저 실행해서 누락 파악 후 문서 생성 | 빠진 문서를 알고 생성해야 품질 보장 |
| 시스템개요서·사용자매뉴얼·개발자가이드 병렬 생성 | 세 문서가 서로 독립적 | 순서 의존성 없음 |
| 납품 전용 문서 별도 카테고리 분류 | 기존 산출물과 구분 | 인수인계 시 신규 생성 문서 명확히 식별 |
| template.md에 자리표시자({사업명} 등) 사용 | 스킬이 실행 시 채움 | AI-DLC 표준 패턴 |
| Word 변환 안내를 패키지 인덱스에 포함 | 이미 Word 파일 있으면 "존재" 표시 | 중복 변환 방지 |

## 스킬별 핵심 설계

### (1) ai-dlc-delivery-checklist — 납품 검수 목록

| 항목 | 내용 |
|:---|:---|
| 트리거 | "납품 검수 목록 만들어줘", "납품 산출물 확인해줘", "인도 문서 체크해줘" |
| 핵심 로직 | Glob으로 프로젝트 전체 탐색 → 필수/권장/선택 분류 → ❌/⚠️/✅ 판정 |
| 필수 항목 | 요구사항정의서, 유즈케이스, 화면정의서, API설계서, 데이터설계서, 코드품질검토, e2e테스트 |
| 권장 항목 | 서비스분류, 비즈니스규칙, 용어사전, 클래스설계서, change-log, 프로그램분석서 |
| 산출물 | `납품검수목록_{사업명}_{YYYYMMDD}.md` |

### (2) ai-dlc-system-overview — 시스템 개요서

| 항목 | 내용 |
|:---|:---|
| 트리거 | "시스템 개요서 만들어줘", "인수인계 개요서 작성해줘", "시스템 요약 문서 만들어줘" |
| 핵심 로직 | 요구사항정의서·유즈케이스·화면목록·API설계서·데이터설계서 통합 → 기술스택·아키텍처·기능목록 추출 |
| ASCII 다이어그램 | 기술스택 기반 계층 아키텍처 자동 생성 |
| 산출물 | `시스템개요서_{사업명}_{YYYYMMDD}.md` |

### (3) ai-dlc-user-manual — 사용자 매뉴얼

| 항목 | 내용 |
|:---|:---|
| 트리거 | "사용자 매뉴얼 만들어줘", "사용 설명서 만들어줘", "화면별 사용법 정리해줘" |
| 핵심 로직 | 화면정의서(SCR-NNN)별 반복 → 목적·진입법·구성·단계별 절차·필드안내·오류메시지 생성 |
| 사용자 그룹 | 페르소나 또는 유즈케이스 액터에서 추출, 없으면 일반사용자/관리자 기본값 |
| 산출물 | `사용자매뉴얼_{사업명}_{YYYYMMDD}.md` |

### (4) ai-dlc-dev-guide — 개발자 가이드

| 항목 | 내용 |
|:---|:---|
| 트리거 | "개발자 가이드 만들어줘", "기술 문서 만들어줘", "인수인계 기술 문서 만들어줘" |
| 핵심 로직 | API설계서+데이터설계서+클래스설계서 + package.json/pom.xml 분석 → Prerequisites·코드구조·API참조·DB스키마·배포 |
| 민감정보 처리 | 환경변수 실제값 대신 `${변수명}` 형태로만 표기 |
| 산출물 | `개발자가이드_{사업명}_{YYYYMMDD}.md` |

### (5) ai-dlc-delivery-package — 납품 패키지 최종화

| 항목 | 내용 |
|:---|:---|
| 트리거 | "납품 패키지 만들어줘", "최종 납품 정리해줘", "납품 인덱스 만들어줘" |
| 핵심 로직 | 전체 산출물 Glob → 카테고리별 분류(아이디어/요구사항/분석/설계/개발검증/변경관리/납품전용) → 인덱스 생성 |
| Word 변환 안내 | 이미 .docx 있으면 "Word 파일 존재" 표시, 없으면 변환 명령어 안내 |
| 산출물 | `납품패키지_인덱스_{사업명}_{YYYYMMDD}.md` |

## 검증 방법

| 스킬 | 검증 시나리오 |
|:---|:---|
| `ai-dlc-delivery-checklist` | 요구사항정의서 없는 디렉터리 → 필수 항목 ❌ 표시 확인 / 전체 있는 디렉터리 → ✅ 납품 가능 표시 |
| `ai-dlc-system-overview` | 요구사항정의서 + 유즈케이스 있을 때 → 기술스택·기능목록·API목록·화면목록 자동 포함 확인 |
| `ai-dlc-user-manual` | 화면정의서 있을 때 → 화면별 단계 절차, 입력필드 안내, 오류 메시지 섹션 생성 확인 |
| `ai-dlc-dev-guide` | API설계서 + 데이터설계서 있을 때 → API 참조 표, DB 스키마 표, 환경 설정 안내 생성 확인 |
| `ai-dlc-delivery-package` | 전체 산출물 있을 때 → 카테고리별 인덱스, Word 변환 안내 포함 확인 |
| 전체 연계 | delivery-checklist → system-overview + user-manual + dev-guide → delivery-package 순서 실행 |
