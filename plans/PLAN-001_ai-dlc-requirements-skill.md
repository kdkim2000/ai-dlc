## Context

AI-DLC(AI-Driven Development Lifecycle) 방법론에 따라 정형화된 한국어 **요구사항 정의서**를 반복적으로 작성해야 한다. 매번 동일한 목차(사업개요 → 사업범위 → 기술스택 → 별지서식 → 버전이력 → 참고문서)를 채우는 작업은 수작업으로는 누락·표기 불일치·ID 채번 오류가 발생하기 쉽다.

이 스킬은 사용자가 자연어로 사업 정보를 제공하면 표준 목차와 표 형식, 일관된 요구사항 ID 체계(FR/PR/SR/QR/IR/DR/CR-NNN)에 맞춰 Markdown 문서를 한 번에 생성하고, **누락된 핵심 정보만 골라 추가로 질문**하는 하이브리드 흐름을 제공한다.

## SKILL.md 핵심 설계

### Frontmatter
```yaml
name: ai-dlc-requirements
description: AI-DLC(AI-Driven Development Lifecycle) 방법론에 따라 한국어 요구사항 정의서(RFP/제안요청서/SI 요구사항서)를 작성해주는 스킬...
```

### 트리거 키워드
`요구사항 정의서`, `AI-DLC`, `RFP`, `제안요청서`, `SI 요구사항`, `요구사항 문서`, `요구사항 명세서`, `사업 요구사항`

### 하이브리드 진행 절차
1. **입력 파싱**: 사업명, 목적/배경, 기간, 예산, 기능 후보, 비기능 후보, 기술스택 키워드 추출
2. **초안 생성**: `template.md`를 읽어 자리표시자(`{{...}}`) 치환
3. **핵심 누락 항목만 묶음 질문** (1회, 3개 이하로 추림):
   - 사업명 / 사업기간 / 사업예산 중 비어 있는 것
   - 추진 배경 한 문장
   - 핵심 기능 3개 미만이면 추가
   - 기술스택 카테고리(FE/BE/DB/Infra) 중 비어 있는 것
4. **답변 반영 후 최종 출력**

### 요구사항 ID 채번 규칙

| 분류 | Prefix | 예시 |
|:---:|:---|:---|
| 기능 | `FR` | FR-001 |
| 성능 | `PR` | PR-001 |
| 보안 | `SR` | SR-001 |
| 품질 | `QR` | QR-001 |
| 인터페이스 | `IR` | IR-001 |
| 데이터 | `DR` | DR-001 |
| 제약 | `CR` | CR-001 |

- 형식: `{PREFIX}-{NNN}` (3자리 0 패딩, 분류별 001부터 순차)
- 한 문서 내 prefix별 독립 채번

### 출력 정책
- **기본**: `./요구사항정의서_{사업명}_{YYYYMMDD}.md` 로 작업 디렉터리에 저장
- **대화창 출력 모드**: `"보여만 줘"`, `"파일 만들지 마"`, `"여기에 출력"` 키워드 감지 시
- 파일 저장 시 절대 경로 + 한 줄 요약(섹션별 채워진 항목 수) 포함
- 동일 파일 존재 시 덮어쓰기 전 확인

## template.md 핵심 구성

- `# 요구사항 정의서` 제목 + 메타 표 (사업명/작성일/버전/작성자)
- 1~6장 목차 완전 배치
  - 2장 1) 요구사항 총괄표: `| 분류 | Prefix | 건수 | 비고 |` 헤더
  - 2장 2)~8): 각 분류별 표 `| ID | 요구사항명 | 설명 | 중요도 | 비고 |`
- 4장 별지서식
  - 기능 요구사항 목록: `| FR-ID | 기능명 | 설명 | 입력 | 출력 | 우선순위 |`
  - 비기능 요구사항 목록: `| ID | 분류 | 요구사항명 | 측정지표 | 목표값 |`
- 5장 문서 버전 이력: `| 버전 | 일자 | 작성자 | 변경 내용 |`
- 6장 참고 문서: bullet list
- 오타 정정: "품지 ㄹ요구사항" → "품질 요구사항"으로 정정

## 작성 원칙

- 표는 GFM 표 문법, 정렬 명시 (`:---`)
- 추측 내용은 `<!-- TODO: 확인 필요 -->` 인라인 주석
- 요구사항 총괄표는 모든 분류 합계를 보여주는 단일 표; 분류별 상세는 별지서식에 분리
- 문서 버전 이력 초기값: `v0.1 / {오늘} / 초안 작성 / 초안 생성`
- 참고 문서 없으면 `_(해당 없음)_` 한 줄로 채움
- 언어: 한국어 고정, 기술 고유명사는 원문 유지

---

## 엣지 케이스

- 입력이 한두 줄로 너무 짧을 때 → 인터뷰 모드로 자동 전환
- 영어 입력 혼재 → 문서는 한국어 통일, 고유명사는 원문 유지
- 동일 파일명 존재 → 덮어쓰기 전 확인

## 검증 방법

1. **자동 트리거 테스트**: `"AI-DLC 방법론으로 사내 출퇴근 관리 시스템 요구사항 정의서 써줘"` → 스킬 자동 호출 + 초안 생성 + 누락 항목 묶음 질문
2. **명시 호출 + 일괄 입력**: 사업명·목적·기능 3개·기술스택 제공 → 추가 질문 거의 없이 파일 생성, FR-001~003 자동 채번 확인
3. **출력 모드 전환**: `"파일 만들지 말고 여기에 보여만 줘"` → 파일 미생성, 대화창 마크다운 출력
4. **ID 채번 검증**: 기능 5개, 보안 2개, 성능 1개 → FR-001~005, SR-001~002, PR-001 분리 채번 확인
5. **엣지 케이스**: 한 줄 입력 → 인터뷰 모드 전환; 동일 파일명 → 덮어쓰기 확인
