# AI-DLC 설계 기초 추출

기존 시스템의 코드분석 산출물(AI-DLC PLAN-003 결과물) 또는 레거시 DDL·API 명세를 읽어 설계단계 진입을 위한 **설계 기초 추출 문서**를 생성한다. 신규 프로젝트가 아닌 레거시/리팩토링 프로젝트에서 설계단계의 시작점이 된다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "설계 기초 뽑아줘", "레거시에서 설계 추출", "기존 API로 설계서 만들어줘"
- "DDL에서 설계 추출", "코드분석 결과로 설계 만들어줘", "기존 산출물로 설계 시작해줘"
- 프로그램 분석서·API 추출 결과·데이터 모델 분석서를 주며 "설계로 전환해줘"라고 할 때

## 입력

- **필수**: 아래 중 1개 이상
  - API 명세 파일 (`ai-dlc-api-spec-extract` 산출물 YAML 또는 기존 Swagger)
  - 데이터 모델 분석서 (`ai-dlc-data-model-analysis` 산출물)
  - 프로그램 분석서 (`ai-dlc-program-spec` 산출물)
  - SQL DDL 파일
- **선택**: 요구사항 정의서 (설계 범위 보정용), 사업명

## 분석 절차

1. **제공 파일 식별**: `Read`로 각 파일 종류 파악 (YAML→API 명세, ERD Mermaid→데이터 모델, 컴포넌트 목록→프로그램 분석서)
2. **API 명세 분석** (있는 경우):
   - 엔드포인트 목록 추출 → 화면·유즈케이스 후보 도출 (GET 목록 → 조회화면, POST → 등록 UC 등)
   - 보안 스킴·권한 정보 → 액터 후보
3. **데이터 모델 분석** (있는 경우):
   - 엔터티·테이블 목록 → 논리 데이터 모델 초안
   - 관계·FK → 도메인 경계 후보
4. **프로그램 분석서 분석** (있는 경우):
   - 주요 컴포넌트·레이어 구조 → 클래스 설계 후보
   - 외부 연계 시스템 → 인터페이스 설계 주의사항
5. **설계 주의사항 도출**: 기술 부채·보안 경고·불명확 항목 정리
6. **`template.md` 기반 설계 기초 추출 문서 생성**

## 산출물 포맷

파일명: `설계기초추출_{사업명}_{YYYYMMDD}.md`

`${CLAUDE_SKILL_DIR}/template.md` 골격 사용:

1. **분석 기준 문서 목록** (제공된 산출물 목록)
2. **도출된 유즈케이스·화면 후보** (API에서 추출)
3. **논리 데이터 모델 초안** (엔터티·관계)
4. **클래스 설계 후보** (컴포넌트·레이어 구조)
5. **액터 및 권한 후보**
6. **설계 시 주의사항** (기술 부채, 불명확 항목)

## 작성 원칙

- 추출 신뢰도가 낮은 항목에 `<!-- TODO: 수동 확인 필요 -->` 표시
- 이 문서는 `ai-dlc-usecase-create`, `ai-dlc-data-design`, `ai-dlc-class-design`의 입력으로 사용됨을 명기
- 실제 요구사항이 없는 경우 역공학 추정임을 결과에 명기

## 엣지 케이스

- **DDL만 있는 경우**: 테이블에서 엔터티 추출 + 유즈케이스는 CRUD 패턴으로 추정
- **API 명세만 있는 경우**: 엔드포인트에서 UC/화면 후보만 도출, 데이터 모델은 요청/응답 스키마로 추정
- **산출물 없음**: 소스코드 경로를 받아 PLAN-003 스킬 선행 실행을 권고
