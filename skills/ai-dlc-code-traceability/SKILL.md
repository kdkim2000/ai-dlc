# AI-DLC 코드-요구사항 추적성 분석

기능 요구사항(FR) 목록과 소스코드를 입력받아 FR ↔ 코드 함수/모듈 매핑을 수행하고 **추적성 매트릭스**를 산출한다. 미구현 요구사항과 요구사항 없는 고아 코드를 함께 식별한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "코드 추적성", "요구사항 추적", "FR 코드 매핑", "기능-코드 연결"
- "traceability matrix", "추적성 매트릭스", "요구사항과 코드 연결해줘"
- "어떤 코드가 어떤 요구사항 구현하는지", "FR 소스 찾아줘"
- FR 목록과 소스코드 경로를 함께 주며 "연결해줘"라고 할 때

## 입력

- **필수**: 분석 대상 소스코드 경로 (디렉터리)
- **선택**: FR 목록 파일 경로 또는 FR 목록을 대화에서 직접 입력

## 분석 절차

1. **FR 목록 수집**: 입력된 FR 목록 파싱 또는 요구사항 문서 파일에서 `FR-\d+` 패턴 `Grep` 추출
2. **소스코드 심볼 수집**: `Glob`으로 소스파일 목록 수집 → `Grep`으로 함수/클래스 선언 추출
3. **키워드 매핑**:
   - FR 기능명에서 핵심 명사/동사 추출 (예: "사용자 로그인" → `login`, `authenticate`, `auth`)
   - 핵심 키워드로 소스코드 `Grep` 탐색
4. **매핑 신뢰도 분류**:
   - **확실(High)**: 함수명·파일명이 FR 키워드와 직접 일치
   - **추정(Medium)**: 의미적으로 유사 (동의어, 영어·한국어 혼용)
   - **미매핑(None)**: 관련 코드를 찾지 못함
5. **고아 코드 탐지**: 어떤 FR에도 매핑되지 않는 Public 함수/클래스 목록 추출
6. **커버리지 계산**: 매핑된 FR 수 / 전체 FR 수 × 100

## 산출물 포맷

파일명: `추적성매트릭스_{시스템명}_{YYYYMMDD}.md`

`${CLAUDE_SKILL_DIR}/template.md` 골격 사용:

1. **FR → 코드 매핑** (전체 FR 커버리지 포함)
2. **미구현 요구사항** (코드에서 발견되지 않은 FR)
3. **고아 코드 후보** (요구사항에 없는 코드)
4. **커버리지 요약** (전체/매핑됨/미매핑 건수, 커버리지 %)

## 매핑 키워드 전략

| FR 키워드 유형 | 탐색 전략 |
|:---|:---|
| 한국어 기능명 | 영어 번역어로 추가 탐색 (예: 로그인 → login, auth) |
| 동사+목적어 | 동사 또는 목적어 단독으로도 탐색 |
| 비즈니스 도메인어 | 도메인 맥락 파일에서 우선 탐색 |

## 작성 원칙

- `node_modules`, `.git`, `dist`, `build`, `__pycache__` 제외
- 테스트 파일(`*.test.*`, `*.spec.*`)은 "테스트 커버리지" 별도 섹션으로 표시
- 매핑 신뢰도가 **추정(Medium)** 이하인 항목에는 `<!-- TODO: 수동 확인 필요 -->` 표시
- FR이 50개 초과 시 미매핑 FR 우선 표시 후 매핑 확인 항목 요약

## 엣지 케이스

- **FR 목록 미제공**: 소스코드 진입점 분석으로 추정 기능 목록 자동 생성 후 매핑 시도
- **단일 파일 프로젝트**: 함수 단위로 매핑
- **다국어 코드베이스**: 언어별 섹션 분리하여 탐색
