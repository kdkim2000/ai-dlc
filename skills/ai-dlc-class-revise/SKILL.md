# AI-DLC 클래스 설계 수정

검증 보고서 또는 자연어 지시에 따라 클래스 설계서(Mermaid classDiagram + 상세 테이블)를 수정하고 버전을 +0.1 증가시켜 새 파일로 저장한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "클래스 설계 수정", "UML 업데이트", "클래스 검증 반영"
- "메서드 추가해줘", "의존관계 수정", "클래스 버전 올려줘", "클래스 다이어그램 수정"
- 검증 보고서를 주며 "반영해줘"라고 할 때
- 클래스 설계서를 주며 "이 클래스 고쳐줘"라고 할 때

## 입력

- **필수**: 기존 클래스 설계서 (`ai-dlc-class-design` 산출물)
- **선택**: 검증 보고서 (`ai-dlc-class-validate` 산출물), 자연어 수정 지시

## 처리 절차

1. **입력 방식 판별**:
   - 검증 보고서 있음 → VI-NNN 이슈 목록에서 변경 사항 자동 추출
   - 검증 보고서 없음 → 자연어 지시에서 변경 사항 파싱
2. **변경 목록 정리**: 클래스 추가/삭제, 속성/메서드 추가/수정, 의존관계 변경
3. **불명확 지시 확인**: 1회만, 3개 이하로 묶어서 질문
4. **변경 적용 (classDiagram + 상세 테이블 동시)**:
   - 클래스 추가: CLS-NNN 최대 번호 +1 채번, 레이어 결정
   - 클래스 삭제: 해당 클래스를 참조하는 의존관계 정리
   - 메서드 추가/수정: 상세 테이블 + classDiagram 표기 동시 갱신
   - 의존관계 변경: classDiagram 화살표 + 상세 의존관계 표 동시 갱신
   - 순환 의존 해소: 인터페이스 추출 또는 이벤트 기반 분리 적용
   - 레이어 위반 해소: 의존 방향 재설계, 중간 레이어 클래스 추가
5. **버전 증가**: 기존 버전 +0.1, 문서 버전 이력 표에 변경 내용 기록
6. **새 파일명으로 저장**: `클래스설계서_{사업명}_{YYYYMMDD}_v{N.N}.md`

## 변경 유형

| 변경 유형 | 처리 방법 |
|:---|:---|
| 클래스 추가 | CLS-NNN +1, classDiagram 노드 추가, 상세 테이블 행 추가 |
| 클래스 삭제 | classDiagram 노드·관계 제거, 참조 클래스의 의존 관계 정리 |
| 속성 추가/수정 | 상세 테이블 + classDiagram 속성 표기 동시 갱신 |
| 메서드 추가/수정 | 상세 테이블 + classDiagram 메서드 표기 동시 갱신 |
| 의존관계 추가/수정 | classDiagram 화살표 + 의존관계 테이블 동시 갱신 |
| 순환 의존 해소 | 인터페이스 추출 시 신규 CLS-NNN 채번 후 classDiagram 재구성 |

## 특이사항

- Mermaid classDiagram과 클래스별 상세 정의 테이블은 **반드시 동시 수정**
- 클래스 삭제 시 시퀀스 다이어그램에서 해당 참여자도 영향받을 수 있음 — 연계 문서 갱신 안내 출력
- UC-클래스 커버리지 표도 변경에 따라 갱신
