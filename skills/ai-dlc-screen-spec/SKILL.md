# AI-DLC 화면 정의서 생성

화면 목록(SCR-NNN)을 기반으로 각 화면의 레이아웃·구성요소·입출력·이벤트·연계 API를 상세 기술한 **화면 정의서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "화면 정의서 만들어줘", "화면 명세서 작성", "UI 스펙 작성", "화면 설계서 생성"
- "화면 상세 정의", "화면 설계해줘", "UI 설계서", "SCR 정의서"
- 화면 목록을 주며 "화면 정의서 만들어줘"라고 할 때

## 입력

- **필수**: 화면 목록 문서 (`ai-dlc-screen-list` 산출물) 또는 UC 문서
- **선택**: API 설계서 (연계 API 매핑용), 도메인 용어사전, 특정 SCR 지정

## 분석 절차

1. **화면 목록 수신**: `Read`로 SCR 목록·유형·UC 연계 파악
2. **SCR별 화면 기본 정보 정리**:
   - 화면명, URL 패턴, 접근 권한, 연계 UC-ID
   - 이전 화면(진입 경로), 다음 화면(이탈 경로)
3. **구성요소 정의** (화면 유형별):
   - LIST: 검색 조건 영역, 결과 테이블(컬럼·정렬), 페이지네이션, 액션 버튼
   - FORM: 입력 필드(타입·필수여부·유효성), 버튼(저장·취소·임시저장)
   - DETAIL: 표시 필드, 수정·삭제·목록 버튼
4. **입력값 명세**: 필드명·타입·필수여부·유효성 규칙·기본값
5. **출력값 명세**: 표시 데이터·형식·정렬 기준
6. **이벤트 처리 흐름**: 버튼클릭·페이지로드·조건변경 시 동작
7. **연계 API 매핑**: API 설계서가 있으면 각 이벤트에 API operationId 연결
8. **`template.md` 기반 화면 정의서 생성**

## 화면 구성요소 기술 방법

레이아웃은 ASCII 텍스트 박스로 표현:
```
+------------------+------------------+
| 검색 조건 영역   |  [검색] [초기화] |
+------------------+------------------+
| 결과 테이블                         |
| 번호 | 이름 | 상태 | 등록일 | 액션 |
+-------------------------------------+
| [등록] [엑셀다운]  페이지: 1/10     |
+-------------------------------------+
```

## 산출물 포맷

파일명: `화면정의서_{사업명}_{YYYYMMDD}.md`

`${CLAUDE_SKILL_DIR}/template.md` 골격 사용:

1. **화면 개요 표** (전체 SCR 목록 요약)
2. **화면별 상세** (SCR별 반복 섹션)
3. **공통 컴포넌트 목록** (재사용 컴포넌트)
4. **화면 흐름도** (주요 화면 간 전환 Mermaid 다이어그램)

## 엣지 케이스

- **화면 수 20개 초과**: 핵심 화면(우선순위 높음) 먼저 상세 작성, 나머지는 기본 정보만 표
- **API 설계서 없음**: 연계 API 컬럼에 `<!-- TODO: API 설계 후 연결 필요 -->` 표시
- **특정 SCR만 요청**: 해당 SCR 상세만 생성 후 전체 화면 목록에서의 위치 명시
