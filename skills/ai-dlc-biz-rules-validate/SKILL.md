# AI-DLC 비즈니스 규칙 검증

비즈니스 규칙 문서(BR 테이블)를 분석해 **모순·중복·모호·누락·형식오류**를 탐지하고 검증 보고서를 생성한다. 검증 결과는 `ai-dlc-biz-rules-revise`에서 수정 시 사용한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 참조.

## 트리거

- "비즈니스 규칙 검증", "BR 검토", "규칙 충돌 확인", "비즈니스 규칙 리뷰"
- "BR 검증해줘", "규칙 오류 찾아줘", "BR 품질 확인"
- 비즈니스 규칙 문서를 보여주며 "이거 검토해줘"라고 할 때

## 검증 항목 (5가지)

### 1. 모순 (Contradiction) — 심각도: 높음
동일하거나 유사한 조건에서 **상반된 행동**이 정의된 규칙 쌍을 탐지.
- 예: `BR-005 "재고 0이면 주문 가능"` vs `BR-012 "재고 0이면 주문 불가"`

### 2. 중복 (Duplication) — 심각도: 중간
**내용이 실질적으로 동일**하거나 포함 관계인 규칙 쌍을 탐지.
- 예: `BR-003 "5회 실패 시 잠금"` vs `BR-018 "로그인 실패 5번이면 계정 비활성화"`

### 3. 모호 (Ambiguity) — 심각도: 중간
조건 또는 행동이 **두 가지 이상으로 해석 가능**한 규칙을 탐지.
- 예: "일정 기간 미사용 시 탈퇴 처리" → "일정 기간"이 구체적이지 않음

### 4. 누락 (Gap) — 심각도: 중간
중요한 **예외 케이스가 처리되지 않은** 규칙 또는 흐름 상의 빈틈을 탐지.
- 예: 결제 성공 규칙은 있으나 결제 실패/타임아웃 처리 규칙이 없음

### 5. 형식오류 (Format Error) — 심각도: 낮음
BR-ID 중복, 필수값(조건/행동/우선순위) 누락, 상태값 오류 등 **구조적 문제** 탐지.

## 진행 절차

1. **문서 수신**: 비즈니스 규칙 문서(텍스트 붙여넣기 또는 파일 경로) 입력받기
2. **전수 검사**: 5가지 검증 항목을 모든 BR에 대해 적용
3. **이슈 목록 작성**: 발견된 이슈를 ID 부여하여 정리
4. **종합 판정**: 이슈 심각도·건수 기준으로 판정
5. **보고서 생성**: 검증 결과 보고서 출력

## 산출물 포맷

파일명: `비즈니스규칙_검증_{YYYYMMDD}.md`

### 검증 요약 표
```
| 검증 항목 | 발견 건수 | 심각도 |
```

### 이슈 목록 표
```
| 이슈-ID | 대상 BR-ID | 이슈 유형 | 설명 | 권고 조치 |
```
- 이슈-ID: VI-NNN (Validation Issue)

### 종합 판정
- **승인**: 이슈 없음 또는 형식오류만 존재
- **조건부 승인**: 모호/중복 이슈 있으나 업무에 큰 지장 없음
- **재검토 필요**: 모순/중요 누락 이슈 존재

## 엣지 케이스

- **이슈가 전혀 없을 때**: "이슈 없음" 판정 + 긍정적 총평
- **모호성 판단이 어려운 경우**: 해석 두 가지를 보여주고 사용자 판단 요청
- **대규모 문서(50개 이상 BR)**: 심각도 높음 이슈만 먼저 보고, 나머지는 별첨 처리
