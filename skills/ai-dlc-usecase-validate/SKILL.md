# AI-DLC 유즈케이스 검증

유즈케이스 문서를 검증하여 누락·불완전·모순·중복·형식오류를 탐지하고 FR-UC 커버리지를 산출하여 **검증 보고서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 유즈케이스 섹션 참조.

## 트리거

- "유즈케이스 검증", "UC 검토", "유즈케이스 리뷰", "UC 품질 확인"
- "유즈케이스 오류 찾아줘", "요구사항-유즈케이스 일관성 확인", "UC 검증해줘"
- 유즈케이스 문서를 주며 "검토해줘"라고 할 때

## 입력

- **필수**: 유즈케이스 문서 파일 (`ai-dlc-usecase-create` 산출물)
- **선택**: 요구사항 정의서 (FR 커버리지 검증용)

## 검증 항목 (5종)

| 유형 | 설명 | 심각도 |
|:---|:---|:---:|
| 누락 | FR이 어떤 UC에도 연결되지 않은 경우 | 높음 |
| 불완전 | 기본 흐름만 있고 예외 흐름이 없는 UC | 중간 |
| 모순 | 액터 권한 정의와 UC 접근 조건 불일치 | 높음 |
| 중복 | 실질적으로 같은 시나리오를 별도 UC로 정의 | 중간 |
| 형식오류 | UC-ID 중복, 필수 섹션(사전조건·사후조건) 누락 | 낮음 |

## 분석 절차

1. **UC 문서 파싱**: `Read`로 유즈케이스 문서 수신, UC-NNN 목록 추출
2. **FR-UC 커버리지 확인**: 요구사항 문서가 있으면 FR-NNN 전체 대비 UC 연계 현황 계산
3. **불완전성 검사**: 예외 흐름 없는 UC, 단계 수 1개 이하인 기본 흐름 탐지
4. **모순 탐지**: 액터 목록과 각 UC의 주요 액터 교차 검증
5. **중복 탐지**: UC명 유사도·기본 흐름 유사도 기반 중복 후보 식별
6. **형식 검사**: UC-ID 채번 연속성, 필수 섹션 존재 여부
7. **VI-NNN 이슈 목록 작성** (001부터 순번)
8. **종합 판정**: 승인 / 조건부 승인 / 재검토 필요

## 판정 기준

| 판정 | 조건 |
|:---|:---|
| 승인 | 높음 이슈 0건, 전체 이슈 3건 이하, FR 커버리지 ≥ 95% |
| 조건부 승인 | 높음 이슈 0건, 전체 이슈 10건 이하, FR 커버리지 ≥ 80% |
| 재검토 필요 | 높음 이슈 1건 이상 또는 FR 커버리지 < 80% |
