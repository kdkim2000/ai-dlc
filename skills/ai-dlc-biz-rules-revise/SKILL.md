# AI-DLC 비즈니스 규칙 수정

기존 비즈니스 규칙 문서에 검증 결과 또는 자연어 변경 지시를 반영하여 **수정된 새 버전**을 생성한다. 변경 이력을 추적 가능하게 유지한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "비즈니스 규칙 수정", "BR 업데이트", "규칙 검증 반영", "BR 수정해줘"
- "비즈니스 규칙 변경", "규칙 수정하고 버전 올려줘"
- 검증 보고서를 보여주며 "이 결과로 BR 수정해줘"라고 할 때
- 특정 규칙을 수정·삭제·추가 요청할 때

## 입력 형식

두 가지 입력 방식을 모두 처리:

**방식 A: 검증 보고서 기반**
- `ai-dlc-biz-rules-validate`의 검증 보고서(VI-NNN 이슈 목록) 제공
- 각 이슈에 대해 권고 조치 적용

**방식 B: 자연어 변경 지시**
- "BR-003을 10회 실패로 변경해줘"
- "BR-015 삭제해줘"
- "배송비 할인 규칙 추가해줘"

## 진행 절차

1. **입력 파악**: 검증 보고서인지 자연어 지시인지 구분
2. **변경 목록 정리**: 수정·삭제·추가 항목 나열
3. **불명확한 지시 확인**: 여러 해석이 가능한 지시는 1회 묶음 질문
4. **수정 적용**: 변경 사항 적용, 영향 받는 규칙(선행/후행 관계) 함께 검토
5. **버전 증가**: 기존 버전 +0.1
6. **새 파일 저장**: `비즈니스규칙_{사업명}_{오늘날짜}_v{버전}.md`

## 산출물 포맷

파일명: `비즈니스규칙_{사업명}_{YYYYMMDD}_v{버전}.md`

### 변경 요약 표 (문서 상단에 추가)
```
| 변경 유형 | 대상 BR-ID | 변경 내용 요약 | 근거 |
```
- 변경 유형: 수정 / 삭제 / 추가

### BR 테이블 내 변경 표시
- 수정된 행: 비고에 `[v{버전} 수정]` 표시
- 삭제된 규칙: 행 삭제 (버전 이력에 "BR-NNN 폐기" 기재)
- 신규 추가 행: 비고에 `[v{버전} 신규]` 표시

### 버전 이력 갱신
기존 버전 이력 표에 행 추가:
```
| v{버전} | {오늘날짜} | 수정 | {변경 내용 한 줄 요약} |
```

## 작성 원칙

- 삭제된 규칙은 테이블에서 제거하되 버전 이력에 BR-ID와 폐기 이유 기록
- 신규 규칙은 기존 도메인 그룹 마지막에 추가, BR-ID는 현재 최대값 +1
- 수정 내용이 연관 규칙에 영향을 줄 경우 해당 규칙도 함께 업데이트 제안

## 엣지 케이스

- **삭제 요청인데 다른 규칙이 참조하는 경우**: 삭제 전 참조 규칙 목록 보여주고 확인
- **신규 규칙 추가 시 중복 가능성**: 유사 규칙 경고 후 추가 여부 확인
- **검증 보고서와 자연어 지시가 동시에 있는 경우**: 검증 보고서 우선 처리 후 자연어 지시 순서로
