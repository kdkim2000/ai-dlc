# AI-DLC 서비스 카탈로그 분류

요구사항 정의서(또는 FR 목록)를 읽어 비즈니스 기능 클러스터별로 묶고, 각 클러스터를 **서비스 단위**로 명명·분류한다. MSA 또는 도메인 주도 설계(DDD)의 바운디드 컨텍스트 개념을 기준으로 한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
산출물 상호 관계: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/artifacts-flow.md` 참조.

## 트리거

- "서비스 분류", "서비스 카탈로그", "마이크로서비스 분류", "서비스 단위로 나눠줘"
- "MSA 서비스 분리", "도메인 분리", "서비스 경계 정의", "바운디드 컨텍스트"
- 요구사항 정의서를 보여주며 "이걸 서비스로 나눠줘"라고 할 때

## 진행 절차

1. **입력 파싱**: FR 항목들(기능명·설명)을 읽어 비즈니스 기능 클러스터로 묶음
   - 클러스터 기준: 동일한 비즈니스 행위자(액터)가 사용하는 기능, 동일 데이터 도메인을 다루는 기능
   - 각 클러스터에 서비스명 부여 (예: 회원관리서비스, 주문서비스, 결제서비스)
2. **분류 기준 확인**: 기본은 MSA 가정. 입력에 "모놀리식", "단일 서비스" 언급이 있으면 모듈 단위로 분류
3. **초안 생성**: `${CLAUDE_SKILL_DIR}/template.md`를 읽어 자리표시자 치환
4. **누락 확인**: 배정되지 않은 FR이 있으면 사용자에게 확인

## 산출물 포맷

파일명: `서비스분류_{사업명}_{YYYYMMDD}.md`

### 서비스 카탈로그 테이블
```
| SC-ID | 서비스명 | 카테고리 | 연관 요구사항 ID | 설명 | 우선순위 |
```
- SC-NNN 형식 자동 채번 (001부터)
- 카테고리: 사용자관리 / 주문·배송 / 결제 / 알림 / 콘텐츠 / 인프라 / 기타 중 선택
- 연관 요구사항 ID: FR-NNN 목록 (쉼표 구분)
- 우선순위: 높음 / 중간 / 낮음

### 서비스별 요약 카드
각 서비스에 대해:
```
#### SC-NNN 서비스명
- **도메인**: 카테고리
- **핵심 기능**: FR-001, FR-002, ...
- **주요 액터**: ...
- **연계 서비스**: SC-NNN (관계 설명)
```

## 작성 원칙

- 하나의 FR이 두 서비스에 걸치는 경우, 주 서비스에 배정하고 비고에 "SC-XXX와 연계" 표시
- 서비스명은 `{도메인}서비스` 또는 `{도메인}Service` 형식으로 통일
- 서비스 수가 15개를 넘으면 상위/하위 서비스 계층으로 분리 제안

## 엣지 케이스

- **FR 목록이 없고 자연어 설명만 있을 때**: 기능 키워드를 추출해 임시 FR로 변환 후 분류
- **서비스 경계가 모호할 때**: 두 후보 모두 보여주고 사용자 선택
- **요구사항 정의서 없이 서비스명만 나열할 때**: 서비스별 카드만 생성하고 FR 연계는 TODO 처리

## 예시

**입력:** "회원 가입/로그인, 상품 목록 조회, 장바구니 담기, 주문 생성, 결제, 주문 취소, 배송 조회, 이메일 알림"

**출력 발췌:**
```markdown
| SC-ID | 서비스명 | 카테고리 | 연관 FR | 설명 |
|:---|:---|:---|:---|:---|
| SC-001 | 회원관리서비스 | 사용자관리 | FR-001, FR-002 | 가입·로그인·인증 |
| SC-002 | 상품서비스 | 콘텐츠 | FR-003 | 상품 목록·검색 |
| SC-003 | 주문서비스 | 주문·배송 | FR-004, FR-005, FR-006, FR-007 | 장바구니·주문·취소·배송 |
| SC-004 | 결제서비스 | 결제 | FR-008 <!-- 별도 FR 필요 --> | 결제 처리 |
| SC-005 | 알림서비스 | 알림 | FR-009 <!-- 별도 FR 필요 --> | 이메일 알림 |
```
