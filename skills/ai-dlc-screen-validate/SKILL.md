# AI-DLC 화면 설계 검증

화면 정의서를 검증하여 UC 커버리지 누락·API 불일치·권한 충돌·UX 결함·형식오류를 탐지하고 **화면 설계 검증 보고서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 화면 설계 섹션 참조.

## 트리거

- "화면 설계 검증", "화면 정의서 검토", "UI 스펙 리뷰", "화면 설계 오류 찾아줘"
- "유즈케이스-화면 일관성 확인", "화면 품질 확인", "화면 검증해줘", "SCR 검증"
- 화면 정의서를 주며 "검토해줘"라고 할 때

## 입력

- **필수**: 화면 정의서 파일 (`ai-dlc-screen-spec` 산출물)
- **선택**: 유즈케이스 문서, API 설계서 (일관성 검증용)

## 검증 항목 (5종)

| 유형 | 설명 | 심각도 |
|:---|:---|:---:|
| 누락 | UC 기본·예외 흐름이 화면으로 표현되지 않은 경우 | 높음 |
| 불일치 | 화면 입출력이 API 파라미터·응답 스키마와 맞지 않는 경우 | 높음 |
| 권한 충돌 | 역할별 접근 정의와 화면 구성요소 표시 조건 불일치 | 중간 |
| UX 결함 | 필수 입력 검증 없음, 오류 메시지 없음, 이탈 경로 없음 | 중간 |
| 형식오류 | SCR-ID 중복, 필수 섹션(URL·접근권한) 누락 | 낮음 |

## 분석 절차

1. **화면 정의서 파싱**: SCR 목록·UC 연계·API 연계 추출
2. **UC-화면 커버리지 확인**: UC 문서가 있으면 UC 흐름 대비 화면 표현 현황 계산
3. **API 불일치 검사**: API 설계서가 있으면 화면 필드 vs. API 스키마 교차 검증
4. **권한 충돌 탐지**: 액터별 접근 정의 vs. 화면 내 조건부 표시 규칙
5. **UX 결함 탐지**:
   - 필수 입력 필드에 유효성 규칙 없음
   - FORM 화면에 오류 메시지 처리 이벤트 없음
   - FORM 화면에 취소/이탈 경로 없음
6. **VI-NNN 이슈 목록 작성**
7. **UC-화면 커버리지 계산**
8. **종합 판정** 산출

## 판정 기준

| 판정 | 조건 |
|:---|:---|
| 승인 | 높음 이슈 0건, 전체 이슈 5건 이하, UC-화면 커버리지 ≥ 90% |
| 조건부 승인 | 높음 이슈 0건, 전체 이슈 15건 이하, UC-화면 커버리지 ≥ 75% |
| 재검토 필요 | 높음 이슈 1건 이상 또는 UC-화면 커버리지 < 75% |
