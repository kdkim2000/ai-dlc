# AI-DLC 데이터 설계 검증

데이터 설계서를 검증하여 정규화 위반·참조 무결성 오류·API 스키마 불일치·명명 규칙 위반·누락을 탐지하고 **데이터 설계 검증 보고서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 데이터 설계 섹션 참조.

## 트리거

- "데이터 설계 검증", "DB 설계 검토", "ERD 검증", "정규화 검토"
- "데이터 모델 품질 확인", "테이블 설계 리뷰", "데이터 설계 오류 찾아줘"
- 데이터 설계서를 주며 "검토해줘"라고 할 때

## 입력

- **필수**: 데이터 설계서 (`ai-dlc-data-design` 산출물)
- **선택**: API 설계서, 유즈케이스 문서 (일관성 검증용)

## 검증 항목 (5종)

| 유형 | 설명 | 심각도 |
|:---|:---|:---:|
| 정규화 위반 | 1NF(반복 그룹)/2NF(부분 종속)/3NF(이행 종속) 위반 | 높음 |
| 참조 무결성 | FK 참조 테이블/컬럼 존재 여부, ON DELETE 정책 미정의 | 높음 |
| API 스키마 불일치 | API 설계서 스키마 필드와 테이블 컬럼 불일치 | 중간 |
| 명명 규칙 위반 | 테이블명/컬럼명 규칙 미준수, PK 컬럼명 규칙 위반 | 낮음 |
| 누락 | PK 없는 테이블, 공통 컬럼(`created_at` 등) 누락, 외래키 인덱스 없음 | 중간 |

## 분석 절차

1. **데이터 설계서 파싱**: 엔터티 목록, 테이블 컬럼, FK 관계 추출
2. **정규화 검사**:
   - 1NF: 반복 그룹 컬럼 탐지 (예: `tag1`, `tag2`, `tag3`)
   - 2NF: 복합 PK 테이블에서 부분 종속 탐지
   - 3NF: 비식별자 컬럼 간 이행 종속 탐지
3. **참조 무결성 검사**: FK 참조 테이블 존재, 참조 컬럼 타입 일치, ON DELETE/UPDATE 정책
4. **API 스키마 일관성**: API 설계서가 있으면 request/response 스키마 필드 vs. 테이블 컬럼 비교
5. **명명 규칙 검사**: 테이블명 대문자, 컬럼명 소문자, PK 컬럼명 패턴
6. **누락 탐지**: PK 없는 테이블, 공통 컬럼 누락, FK 인덱스 누락
7. **VI-NNN 이슈 목록 작성**
8. **종합 판정** 산출

## 판정 기준

| 판정 | 조건 |
|:---|:---|
| 승인 | 높음 이슈 0건, 전체 이슈 5건 이하 |
| 조건부 승인 | 높음 이슈 0건, 전체 이슈 15건 이하 |
| 재검토 필요 | 높음 이슈 1건 이상 |
