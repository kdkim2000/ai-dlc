# AI-DLC 도메인 표준 용어 검증

도메인 표준 용어사전(TM 테이블)을 분석해 **정의 모호성·동의어 충돌·도메인 불일치·미사용 용어·형식오류**를 탐지하고 검증 보고서를 생성한다. 검증 결과는 `ai-dlc-glossary-revise`에서 수정 시 사용한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 참조.

## 트리거

- "도메인 용어 검증", "용어사전 검토", "용어 충돌 확인", "글로서리 검증"
- "용어사전 리뷰", "용어 오류 찾아줘", "용어 품질 확인"
- 용어사전 문서를 보여주며 "이거 검토해줘"라고 할 때

## 검증 항목 (5가지)

### 1. 정의 모호성 (Ambiguous Definition) — 심각도: 높음
정의가 **순환 참조**되거나 너무 짧아 의미를 파악하기 어려운 용어 탐지.
- 예: `"주문 = 주문 행위"` (순환), `"회원 = 사람"` (너무 짧음)

### 2. 동의어 충돌 (Synonym Conflict) — 심각도: 높음
같은 개념을 표현하는 두 용어가 **별개의 용어로 각각 정의**된 경우 탐지.
- 예: "회원"과 "사용자"가 각각 독립 항목으로 유사한 정의를 가짐

### 3. 도메인 불일치 (Domain Mismatch) — 심각도: 중간
용어의 내용이 배정된 도메인과 맞지 않는 경우 탐지.
- 예: "결제수단"이 "사용자관리" 도메인으로 분류됨

### 4. 미사용 용어 (Unused Term) — 심각도: 낮음 (선택적 검증)
요구사항 문서가 함께 제공된 경우, 해당 문서 어디에도 **등장하지 않는 용어** 탐지.
- 요구사항 문서가 없으면 이 항목은 검증 생략

### 5. 형식오류 (Format Error) — 심각도: 낮음
TM-ID 중복, 정의 누락, 상태값 오류 등 **구조적 문제** 탐지.

## 진행 절차

1. **문서 수신**: 용어사전(텍스트 붙여넣기 또는 파일 경로) 입력받기
   - 요구사항 문서도 함께 제공하면 미사용 용어 검증 가능
2. **전수 검사**: 5가지 검증 항목을 모든 TM에 대해 적용
3. **이슈 목록 작성**: 발견된 이슈를 ID 부여하여 정리
4. **종합 판정**: 이슈 심각도·건수 기준으로 판정
5. **보고서 생성**: 검증 결과 보고서 출력

## 산출물 포맷

파일명: `용어사전_검증_{YYYYMMDD}.md`

### 검증 요약 표
```
| 검증 항목 | 발견 건수 | 심각도 |
```

### 이슈 목록 표
```
| 이슈-ID | 대상 TM-ID | 이슈 유형 | 설명 | 권고 조치 |
```
- 이슈-ID: VI-NNN (Validation Issue)

### 종합 판정
- **승인**: 이슈 없음 또는 형식오류만 존재
- **조건부 승인**: 도메인 불일치/미사용 용어만 존재
- **재검토 필요**: 정의 모호성/동의어 충돌 이슈 존재

## 엣지 케이스

- **이슈가 전혀 없을 때**: "이슈 없음" 판정 + 긍정적 총평
- **동의어 충돌이 의도적인 경우**: 사용자에게 확인 요청 (예: 도메인에 따라 다른 의미로 사용하는 경우)
- **소규모 용어사전 (20개 이하)**: 전체를 한 번에 검토 후 이슈 종합
