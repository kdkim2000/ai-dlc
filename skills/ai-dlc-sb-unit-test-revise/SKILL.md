# AI-DLC 단위 테스트 코드 수정 (검증 반영)

`ai-dlc-sb-unit-test-validate` 검증 보고서의 VI-NNN 이슈를 기반으로 **테스트 케이스 추가·수정·삭제**를 실제 파일에 반영한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "테스트 코드 수정", "테스트 검증 반영", "테스트 커버리지 보완"
- "테스트 코드 개선", "누락된 테스트 추가", "테스트 케이스 보완"

## 입력

- **필수**: 검증 보고서 (`ai-dlc-sb-unit-test-validate` 산출물) 또는 이슈 설명
- **필수**: 대상 테스트 코드 파일 경로
- **선택**: 대상 소스 코드 (Service/Controller) — 테스트 케이스 내용 확인용

## 수정 절차

1. **이슈 목록 파악**: VI-NNN 이슈 코드·파일명·라인·수정 방안 읽기
2. **이슈 유형별 수정 패턴**:

   | 이슈 코드 | 수정 패턴 |
   |:---|:---|
   | CO-003 (경계값 누락) | `@Test` 메서드 추가: null/빈값/최대값 케이스 |
   | CO-004 (예외 케이스 누락) | `assertThrows` / `status().is4xxClientError()` 추가 |
   | TA-001 (@ExtendWith 누락) | 클래스 상단 어노테이션 추가 |
   | TA-003 (@DisplayName 누락) | 각 `@Test` 메서드에 `@DisplayName` 추가 |
   | MO-002 (verify 남용) | verify 제거 후 결과값 직접 검증으로 대체 |
   | IN-001 (상태 공유) | `@BeforeEach`로 픽스처 이동 |

3. **코드 위치 특정**: Glob/Read로 파일 확인 후 Edit 도구로 수정
4. **수정 후 검증**: 수정된 메서드가 기존 테스트와 충돌하지 않는지 확인
5. **변경 이력 주석**: 클래스 상단에 수정 이력 주석 추가

## 수정 원칙

- **최소 변경**: 이슈에 지목된 부분만 수정, 불필요한 리팩터링 금지
- **기존 테스트 보존**: 기존 통과 테스트를 깨뜨리지 않도록 주의
- **명명 일관성**: 기존 메서드명 패턴(`success`, `fail`, `notFound` 등) 유지
- **테스트 독립성**: 추가하는 케이스가 다른 테스트에 영향 없도록 격리

## 산출물

- 수정된 테스트 코드 파일 (`src/test/java/.../*Test.java`)
- 수정 완료 요약 (대화창 출력): VI-NNN → 적용 결과 표
