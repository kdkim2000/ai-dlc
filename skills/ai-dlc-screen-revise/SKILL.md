# AI-DLC 화면 설계 수정

검증 보고서 또는 자연어 지시에 따라 화면 정의서를 수정하고 버전을 +0.1 증가시켜 새 파일로 저장한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "화면 설계 수정", "화면 정의서 업데이트", "화면 검증 반영", "화면 수정해줘"
- "SCR 변경", "화면 버전 올려줘", "화면 추가해줘", "UI 스펙 수정"
- 검증 보고서를 주며 "반영해줘"라고 할 때
- 화면 정의서를 주며 "이 화면 고쳐줘"라고 할 때

## 입력

- **필수**: 기존 화면 정의서 (`ai-dlc-screen-spec` 산출물)
- **선택**: 검증 보고서 (`ai-dlc-screen-validate` 산출물), 자연어 수정 지시

## 처리 절차

1. **입력 방식 판별**:
   - 검증 보고서 있음 → VI-NNN 이슈 목록에서 변경 사항 자동 추출
   - 검증 보고서 없음 → 자연어 지시에서 변경 사항 파싱
2. **변경 목록 정리**: 화면 추가/삭제, 필드·이벤트·API 매핑 변경
3. **불명확 지시 확인**: 1회만, 3개 이하로 묶어서 질문
4. **변경 적용**:
   - 화면 추가 시 SCR-NNN 최대 번호 +1 채번
   - 화면 삭제 시 화면 흐름도·역할별 접근 매핑 동시 갱신
   - API 연계 변경 시 이벤트 처리 섹션 동시 갱신
5. **버전 증가**: 기존 버전 +0.1, 문서 버전 이력 표에 변경 내용 기록
6. **새 파일명으로 저장**: `화면정의서_{사업명}_{YYYYMMDD}_v{N.N}.md`

## 변경 유형

| 변경 유형 | 처리 방법 |
|:---|:---|
| 화면 추가 | 최대 SCR-NNN +1, 화면 흐름도에 노드 추가 |
| 화면 삭제 | 삭제 이유 이력 기록, 연결 화면 이탈경로 갱신 |
| 필드 추가/수정 | 해당 SCR 입력/출력 항목 테이블 수정 |
| 이벤트 추가/수정 | 이벤트 처리 테이블 수정, API 연계 동시 갱신 |
| 권한 변경 | 해당 SCR + 역할별 접근 화면 매핑 표 동시 수정 |
