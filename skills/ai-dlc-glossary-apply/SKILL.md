# AI-DLC 서비스 요구사항 표준 용어 반영

요구사항 정의서(또는 기타 분석 산출물)에서 **비표준 표현을 탐지**하고, 도메인 표준 용어사전의 확정 용어로 **치환**하여 문서 전체의 용어 일관성을 확보한다. 분석단계의 최종 통합 스킬이다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "표준 용어 반영", "용어 통일", "요구사항에 용어사전 적용", "글로서리 적용"
- "용어 일관성 맞춰줘", "요구사항 용어 표준화", "용어 치환"
- 요구사항 문서와 용어사전을 함께 보여주며 "용어 통일해줘"라고 할 때

## 필요 입력

1. **요구사항 문서**: 텍스트 붙여넣기 또는 파일 경로 (필수)
2. **도메인 표준 용어사전**: 텍스트 붙여넣기 또는 파일 경로 (필수)
   - 없으면 "용어사전이 필요합니다. `ai-dlc-glossary-create`로 먼저 생성해주세요" 안내

## 진행 절차

1. **용어사전 로드**: TM 테이블에서 확정(`확정`) 상태인 용어만 추출
2. **비표준 표현 탐색**: 용어사전의 "동의어/유사어" 목록을 요구사항 문서 전체에서 검색
3. **치환 후보 목록 작성**: 탐지된 모든 비표준 표현 → 대표 표준 용어 매핑
4. **모호한 치환 확인**: 문맥에 따라 치환 여부가 불명확한 항목을 묶어 1회 사용자 확인
5. **치환 적용**: 승인된 항목 치환, 거부된 항목은 그대로 유지
6. **출력**: 수정된 요구사항 문서 + 치환 요약 리포트

## 산출물

**A. 수정된 요구사항 문서**
- 파일명: `요구사항정의서_{사업명}_{YYYYMMDD}_표준용어적용.md`
- 치환된 용어는 문서 내에서 **볼드(강조)**로 표시해 리뷰어가 확인 가능하게 함
- 문서 버전 이력에 "표준 용어 반영 (용어사전 v{버전})" 행 추가

**B. 치환 요약 리포트 (문서 하단 또는 별도 섹션)**
```
| 원래 표현 | 대체 표준 용어 (TM-ID) | 등장 횟수 | 처리 결과 |
```
- 처리 결과: `치환 완료` / `사용자 유지 결정` / `확인 중`

## 작성 원칙

- 초안(상태: "초안") 용어는 치환 대상에서 제외 — 확정 용어만 적용
- 치환 시 문장 의미가 바뀌는 경우: 치환하지 않고 `<!-- TODO: 수동 확인 필요 -->` 표시
- 대소문자·조사 변형 처리: "회원이" / "회원을" / "회원의" 모두 같은 용어로 인식
- 복합어 처리: "구매 회원" 안의 "회원"은 치환, "비회원 접속" 안의 "회원"은 의미 확인 후 처리

## 엣지 케이스

- **용어사전에 확정 용어가 없는 경우**: "확정 용어 없음" 안내 + `ai-dlc-glossary-revise`로 상태 변경 권고
- **하나의 비표준 표현이 여러 표준 용어로 매핑 가능한 경우**: 모두 보여주고 사용자 선택
- **용어사전 없이 요청한 경우**: `ai-dlc-glossary-create` 사용 안내
- **이미 표준 용어가 잘 적용된 문서**: 비표준 표현 0건 탐지 후 "이미 표준화된 문서입니다" 결과 보고

## 예시

**입력:** 요구사항 문서에 "고객", "유저", "사용자"가 혼용됨. 용어사전에 "회원"(TM-001)이 확정 대표 용어, "고객/유저/사용자"가 동의어로 등록됨.

**치환 요약 리포트 발췌:**
```markdown
| 원래 표현 | 대체 표준 용어 | 등장 횟수 | 처리 결과 |
|:---|:---|:---:|:---|
| 고객 | 회원 (TM-001) | 7 | 치환 완료 |
| 유저 | 회원 (TM-001) | 3 | 치환 완료 |
| 사용자 | 회원 (TM-001) | 12 | 치환 완료 |
```
> 총 22개 표현을 "회원"으로 통일했습니다.
