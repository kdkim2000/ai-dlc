# AI-DLC 도메인 표준 용어 수정

기존 도메인 표준 용어사전에 검증 결과 또는 자연어 변경 지시를 반영하여 **수정된 새 버전**을 생성한다. 변경 이력을 추적 가능하게 유지한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "도메인 용어 수정", "용어사전 업데이트", "용어 검증 반영"
- "용어사전 수정해줘", "용어 추가해줘", "용어 정의 바꿔줘"
- 검증 보고서를 보여주며 "이 결과로 용어사전 수정해줘"라고 할 때
- 특정 용어를 수정·삭제·추가 요청할 때

## 입력 형식

두 가지 입력 방식을 모두 처리:

**방식 A: 검증 보고서 기반**
- `ai-dlc-glossary-validate`의 검증 보고서(VI-NNN 이슈 목록) 제공
- 각 이슈에 대해 권고 조치 적용

**방식 B: 자연어 변경 지시**
- "TM-005의 정의를 더 명확하게 바꿔줘"
- "TM-012 삭제하고 TM-003 동의어에 추가해줘"
- "배송추적 용어 추가해줘"

## 진행 절차

1. **입력 파악**: 검증 보고서인지 자연어 지시인지 구분
2. **변경 목록 정리**: 수정·삭제·추가·통합(동의어 처리) 항목 나열
3. **불명확한 지시 확인**: 여러 해석이 가능한 지시는 1회 묶음 질문
4. **수정 적용**: 변경 사항 적용
5. **버전 증가**: 기존 버전 +0.1
6. **새 파일 저장**: `용어사전_{사업명}_{오늘날짜}_v{버전}.md`

## 산출물 포맷

파일명: `용어사전_{사업명}_{YYYYMMDD}_v{버전}.md`

### 변경 요약 표 (문서 상단에 추가)
```
| 변경 유형 | 대상 TM-ID | 변경 내용 요약 | 근거 |
```
- 변경 유형: 정의수정 / 삭제 / 추가 / 동의어통합 / 도메인변경

### TM 테이블 내 변경 표시
- 수정된 행: 비고에 `[v{버전} 수정]` 표시
- 삭제된 용어: 행 삭제 (버전 이력에 기재)
- 신규 추가 행: 비고에 `[v{버전} 신규]` 표시

### 버전 이력 갱신
기존 버전 이력 표에 행 추가:
```
| v{버전} | {오늘날짜} | 수정 | {변경 내용 한 줄 요약} |
```

## 작성 원칙

- 동의어 통합으로 용어가 삭제될 때: 삭제된 용어를 대표 용어의 동의어/유사어 컬럼에 추가
- 새 용어 추가 시 기존 최대 TM-ID + 1로 채번
- 도메인 변경 시 관련 용어 그룹의 일관성도 함께 확인

## 엣지 케이스

- **삭제 용어가 다른 용어 정의에서 참조되는 경우**: 참조 용어 목록 보여주고 확인
- **대표 용어 변경 시 (A를 버리고 B를 대표로)**: 모든 문서에서 A → B 치환 필요성 안내 (`ai-dlc-glossary-apply` 사용 권고)
- **대규모 수정 (10개 이상) 시**: 변경 요약 표를 먼저 보여주고 사용자 승인 후 반영
