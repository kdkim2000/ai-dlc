# AI-DLC 클래스 설계 검증

클래스 설계서를 검증하여 순환 의존·SRP 위반·레이어 경계 위반·UC 커버리지 누락·형식오류를 탐지하고 **클래스 설계 검증 보고서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
품질 기준: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/quality-checklist.md` 클래스 설계 섹션 참조.

## 트리거

- "클래스 설계 검증", "UML 검토", "클래스 다이어그램 리뷰"
- "SOLID 원칙 확인", "레이어 의존성 검토", "클래스 설계 오류 찾아줘"
- 클래스 설계서를 주며 "검토해줘"라고 할 때

## 입력

- **필수**: 클래스 설계서 (`ai-dlc-class-design` 산출물)
- **선택**: 유즈케이스 문서, API 설계서 (커버리지 검증용)

## 검증 항목 (5종)

| 유형 | 설명 | 심각도 |
|:---|:---|:---:|
| 순환 의존 | A→B→C→A 형태의 순환 참조 탐지 | 높음 |
| SRP 위반 | 단일 클래스 메서드 수 > 10개 (휴리스틱 기준) | 중간 |
| 레이어 경계 위반 | Controller→Repository 직접 참조 등 레이어 건너뜀 | 높음 |
| UC 커버리지 누락 | UC 기본 흐름 단계가 클래스 메서드로 표현되지 않은 경우 | 중간 |
| 형식오류 | CLS-ID 중복, 속성/메서드 타입 미정의, 필수 섹션 누락 | 낮음 |

## 분석 절차

1. **클래스 설계서 파싱**: CLS 목록, 레이어, 의존 관계 추출
2. **순환 의존 탐지**: 의존 관계 그래프에서 사이클 탐지
   - 양방향 참조, 3개 이상 클래스 간 순환 경로
3. **SRP 검사**: 메서드 수 > 10개 클래스 목록화, 책임 분리 제안
4. **레이어 경계 검사**: 
   - Controller가 Repository를 직접 참조
   - Domain이 Service를 역참조
   - 허용된 레이어 의존 방향 위반 탐지
5. **UC 커버리지**: UC 문서가 있으면 UC 흐름 단계 → Service 메서드 매핑
6. **형식오류 탐지**: CLS-ID 중복, 타입 미정의 속성/메서드
7. **VI-NNN 이슈 목록 작성**
8. **UC-클래스 커버리지 계산**
9. **종합 판정** 산출

## 판정 기준

| 판정 | 조건 |
|:---|:---|
| 승인 | 높음 이슈 0건, 전체 이슈 5건 이하, UC-클래스 커버리지 ≥ 90% |
| 조건부 승인 | 높음 이슈 0건, 전체 이슈 15건 이하, UC-클래스 커버리지 ≥ 75% |
| 재검토 필요 | 높음 이슈 1건 이상 또는 UC-클래스 커버리지 < 75% |
