# 요구사항 ID 코드표 및 분류 가이드

요구사항을 어느 분류에 넣을지 애매할 때 이 문서를 기준으로 결정한다.

## Prefix 코드표

| Prefix | 분류 | 의미 |
|:---:|:---|:---|
| `FR` | 기능 요구사항 (Functional) | 사용자가 수행할 수 있는 행위·시스템이 제공하는 기능 |
| `PR` | 성능 요구사항 (Performance) | 정량적으로 측정 가능한 속도·처리량·동시성 |
| `SR` | 보안 요구사항 (Security) | 인증·인가·암호화·감사·개인정보 보호 |
| `QR` | 품질 요구사항 (Quality) | 가용성·신뢰성·유지보수성·이식성 등 ISO/IEC 25010 품질 속성 |
| `IR` | 인터페이스 요구사항 (Interface) | 외부 시스템 연계·API·프로토콜·파일 포맷 교환 |
| `DR` | 데이터 요구사항 (Data) | 데이터 모델·수집·보관·삭제·마이그레이션 |
| `CR` | 제약사항 (Constraint) | 법규·표준·기술·예산·일정·조직 정책상의 제약 |

## 분류 판단 가이드

판단이 애매한 항목은 아래 우선순위로 분류한다.

### 1) FR vs 그 외
- "사용자가 X를 할 수 있다", "시스템이 Y를 제공한다" → **FR**
- "X를 N초 안에 처리한다", "동시 N명을 지원한다" → **PR**
- "X 시 인증을 거친다", "Y는 암호화한다" → **SR**

### 2) PR (성능) 판별 키워드
- 응답시간, 처리량(TPS/RPS), 동시접속자수, 처리 건수/일, 배치 처리 시간
- 페이지 로드 시간, 검색 결과 반환 시간

### 3) SR (보안) 판별 키워드
- 인증/로그인/SSO/JWT/OAuth/2FA
- 인가/권한/RBAC/ACL
- 암호화(저장·전송)/TLS/HTTPS
- 개인정보·민감정보 처리, 감사로그, 접근통제
- 보안 표준 준수(ISMS, ISO 27001 등)

### 4) QR (품질) 판별 키워드 — ISO/IEC 25010 기준
- **가용성**: 가동률(예: 99.9%), 장애 복구 시간(RTO/RPO)
- **신뢰성**: MTBF, 오류 발생률
- **유지보수성**: 모듈화, 코드 품질 지표, 문서화 수준
- **이식성**: 멀티 플랫폼 지원, 컨테이너화
- **사용성**: 접근성(WCAG), 학습 용이성
- **호환성**: 브라우저/OS 지원 범위

### 5) IR (인터페이스) 판별 키워드
- 외부 시스템 연계(ERP, SSO, 결제, SMS, 이메일 게이트웨이)
- Open API 제공·소비
- 파일/메시지 포맷 교환(EDI, CSV 배치, Kafka 토픽)
- 표준 프로토콜(REST, GraphQL, gRPC, SOAP)

### 6) DR (데이터) 판별 키워드
- 데이터 모델/스키마/엔터티
- 데이터 수집·정제·보관 기간·삭제 정책
- 마스터 데이터·코드 체계
- 마이그레이션·백업·복구
- 데이터 품질 기준(정합성·완전성·정확성)

### 7) CR (제약사항) 판별 키워드
- 법규·규정(개인정보보호법, 전자금융감독규정 등)
- 표준 준수 의무(국가표준, 사내 표준)
- 사용 가능 기술 제한(특정 벤더 솔루션 사용 의무)
- 예산·일정·인력 제약
- 운영 환경 제약(특정 클라우드, 망분리 환경)

## 흔히 헷갈리는 케이스

| 케이스 | 분류 | 이유 |
|:---|:---:|:---|
| "JWT로 인증한다" | SR | 인증 방식은 보안 |
| "JWT 토큰 발급 API를 제공한다" | FR + IR | 기능이자 외부 인터페이스 |
| "응답시간 1초 이내" | PR | 정량 성능 지표 |
| "99.9% 가용성" | QR | 품질 속성(신뢰성) |
| "개인정보는 AES-256으로 암호화" | SR | 보안 통제 |
| "개인정보 보유 기간은 3년" | DR + CR | 데이터 보관 정책이자 법적 제약 (둘 다 등록 가능) |
| "AWS Seoul Region 사용 의무" | CR | 운영 환경 제약 |
| "REST API로 외부에 공개" | IR | 외부 인터페이스 |
| "감사로그를 남긴다" | SR | 보안 통제(감사) |
| "장애 발생 시 5분 내 복구" | QR | 가용성(RTO) |

## 채번 규칙 재확인

- 형식: `{PREFIX}-{NNN}` (예: `FR-001`, `SR-012`)
- 분류별 독립 채번 — FR과 PR이 동시에 `001`을 가질 수 있음.
- 한 항목이 두 분류에 걸치면(예: 위 표의 "개인정보 보유 기간 3년") **각 분류에 별도 ID로 등록**하고 "비고"에 상호 참조를 적는다 (예: `DR-003 (CR-002와 연계)`).
