# AI-DLC 기능 요구사항 정의

요구사항 초안·메모·회의록을 분석해 기능 요구사항을 **심화 정의**한다. `ai-dlc-requirements`의 기본 FR 표보다 **액터, 사전조건, 사후조건, 예외 흐름**을 추가해 개발자와 테스터가 바로 활용할 수 있는 수준으로 작성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "기능 요구사항 정의", "기능 요구사항 도출", "FR 작성", "유스케이스 정의"
- "기능 명세 작성", "기능 요구사항 상세화", "기능 명세서"
- 요구사항 초안·메모를 보여주며 "이걸 FR로 정의해줘"라고 할 때

## 기존 `ai-dlc-requirements`와의 차이

| 항목 | ai-dlc-requirements | ai-dlc-functional-req |
|:---|:---|:---|
| 목적 | 전체 요구사항 정의서 생성 | 기능 요구사항 심화 분석 |
| 액터 | 없음 | 있음 |
| 사전조건 | 없음 | 있음 |
| 사후조건 | 없음 | 있음 |
| 예외 흐름 | 없음 | 있음 |
| 서비스 연계 | 없음 | SC-NNN 참조 |

## 진행 절차

1. **입력 파싱**: 기능 키워드(동사+목적어) 추출, 액터 추론
2. **FR 생성**: `${CLAUDE_SKILL_DIR}/template.md`를 읽어 각 기능을 심화 정의
3. **핵심 누락 확인** (묶어서 1회 질문):
   - 주요 액터 미확인 시
   - 중요한 예외 흐름 (실패/오류) 키워드 누락 시
4. **기존 요구사항 정의서와 ID 연계**: 기존 FR-NNN이 있으면 그 ID 그대로 사용

## 산출물 포맷

파일명: `기능요구사항_{사업명}_{YYYYMMDD}.md`

### 기능 요구사항 심화 테이블
```
| FR-ID | 기능명 | 서비스(SC-ID) | 액터 | 설명 | 사전조건 | 사후조건 | 예외 흐름 | 우선순위 |
```
- 우선순위: 필수 / 높음 / 중간 / 낮음
- 예외 흐름: 1~2줄로 간결하게 (예: "입력 오류 시 오류 메시지 표시")

### 유스케이스 개요 섹션 (선택)
기능이 5개 이상이거나 흐름이 복잡한 서비스에 대해 유스케이스 텍스트 다이어그램 추가:
```
액터 → [기능명] → 시스템 응답
              ↘ [예외 흐름]
```

## 작성 원칙

- FR-ID는 기존 문서의 ID를 재사용하거나, 없으면 FR-001부터 새로 채번
- 서비스(SC-ID) 컬럼: 서비스 카탈로그 분류 결과가 있으면 연계, 없으면 `<!-- TODO -->`
- 사전조건은 "~인 상태에서" 형식으로 작성
- 사후조건은 "~이 완료된다" 형식으로 작성

## 엣지 케이스

- **입력이 이미 FR 테이블인 경우**: 심화 컬럼(액터·사전/사후조건) 추가해서 확장
- **액터를 특정할 수 없는 경우**: "사용자" (비로그인), "회원" (로그인), "관리자" 세 가지 기본 액터로 추론
- **예외 흐름이 너무 많은 경우**: 주요 예외 2~3개만 표에 기재, 나머지는 별도 예외 처리 섹션 추가

## 예시

**입력:** "회원이 로그인한다. 이메일과 비밀번호 입력. 잘못되면 오류."

**출력 발췌:**
```markdown
| FR-ID | 기능명 | 서비스 | 액터 | 설명 | 사전조건 | 사후조건 | 예외 흐름 | 우선순위 |
|:---|:---|:---|:---|:---|:---|:---|:---|:---:|
| FR-001 | 로그인 | SC-001 회원관리서비스 | 비회원(미인증 사용자) | 이메일·비밀번호로 인증 후 세션 생성 | 회원 가입이 완료된 상태 | 인증 토큰이 발급되고 메인 페이지로 이동 | 이메일/비밀번호 불일치 시 "인증 실패" 메시지 표시, 5회 실패 시 계정 잠금 | 필수 |
```
