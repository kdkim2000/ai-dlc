# AI-DLC 비기능 요구사항 정의

요구사항 초안·메모·회의록을 분석해 비기능 요구사항(PR/SR/QR/IR/DR/CR)을 **심화 정의**한다. `ai-dlc-requirements`의 기본 비기능 표보다 **측정 단위 명시와 검증방법**을 추가해 테스트 계획에 바로 활용 가능한 수준으로 작성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.
ID 분류 가이드: `${CLAUDE_SKILL_DIR}/../ai-dlc-requirements/references/id-codes.md` 참조 (동일 체계 사용).

## 트리거

- "비기능 요구사항 정의", "NFR 작성", "비기능 명세 작성"
- "성능 요구사항 정의", "보안 요구사항 정의", "품질 요구사항 정의"
- "SLA 정의", "가용성 정의", "성능 기준 명세"
- 요구사항 초안을 보여주며 "비기능 요구사항 뽑아줘"라고 할 때

## 진행 절차

1. **입력 파싱**: 비기능 관련 키워드 추출 (응답시간·동시접속·인증·암호화·가용성 등)
2. **분류 결정**: `ai-dlc-requirements/references/id-codes.md` 기준으로 PR/SR/QR/IR/DR/CR 분류
3. **목표값 수치화**: 정성적 표현을 정량 목표값으로 변환 (예: "빠르게" → "응답시간 1초 이내(p95)")
4. **검증방법 추가**: 각 항목에 어떻게 테스트할지 명시
5. **초안 생성**: `${CLAUDE_SKILL_DIR}/template.md` 기반 작성
6. **누락 수치 확인**: 측정 단위가 없는 목표값 항목을 묶어 1회 질문

## 산출물 포맷

파일명: `비기능요구사항_{사업명}_{YYYYMMDD}.md`

### 비기능 요구사항 심화 테이블
```
| ID | 분류 | 요구사항명 | 측정지표 | 목표값(단위 포함) | 검증방법 | 우선순위 |
```
- 측정지표 예: 응답시간, TPS, 동시접속자수, 가동률, MTTR
- 목표값 예: "1초 이하 (p95)", "99.9%", "300명"
- 검증방법 예: "JMeter 부하테스트", "OWASP ZAP 자동화 스캔", "모니터링 대시보드 30일 관측"
- 우선순위: 필수 / 높음 / 중간 / 낮음

## 작성 원칙

- **측정 불가 표현 금지**: "빠르게", "안전하게", "쉽게" → 반드시 수치화
- **목표값 형식**: `{수치} {단위} ({조건})` 예: `2초 이하 (일반 조회, p95, 동시접속 100명)`
- 분류가 애매하면 `ai-dlc-requirements/references/id-codes.md`의 "흔히 헷갈리는 케이스" 표 참조
- 한 항목이 두 분류에 걸치면 각 분류에 별도 ID, 비고에 상호 참조

## 엣지 케이스

- **수치화 불가한 경우**: `<!-- TODO: 목표값 수치 확인 필요 -->` 표시 후 진행
- **법적 요구사항인 경우**: CR로 분류, 근거 법령을 비고에 기재
- **입력에 비기능 항목이 전혀 없는 경우**: 일반적인 SI 프로젝트 기본값을 제안 (응답시간 3초 이내, 가동률 99.5% 등)

## 예시

**입력:** "동시접속 300명 지원, JWT 인증, AWS 배포, 개인정보보호법 준수"

**출력 발췌:**
```markdown
| ID | 분류 | 요구사항명 | 측정지표 | 목표값 | 검증방법 | 우선순위 |
|:---|:---:|:---|:---|:---|:---|:---:|
| PR-001 | 성능 | 동시접속 처리 | 동시접속자수 | 300명 이상 (응답시간 3초 이내 유지) | JMeter 동시접속 부하테스트 | 필수 |
| SR-001 | 보안 | 사용자 인증 | JWT 토큰 인증 방식 | JWT 액세스토큰 유효기간 30분, 리프레시토큰 7일 | 인증 흐름 통합테스트 | 필수 |
| SR-002 | 보안 | 개인정보보호 | 개인정보보호법 준수 여부 | 법 제29조 안전성 확보조치 이행 | 개인정보 영향평가 | 필수 |
| CR-001 | 제약 | 클라우드 인프라 | AWS 사용 의무 | AWS Seoul Region 사용 | 인프라 배포 확인 | 필수 |
```
