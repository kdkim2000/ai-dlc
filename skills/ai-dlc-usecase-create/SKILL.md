# AI-DLC 유즈케이스 시나리오 생성

요구사항 정의서·FR 목록·서비스 카탈로그를 기반으로 표준 유즈케이스 시나리오(기본 흐름·대안 흐름·예외 흐름)와 Mermaid 유즈케이스 다이어그램을 포함한 **유즈케이스 문서**를 생성한다.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "유즈케이스 작성", "유즈케이스 시나리오 만들어줘", "UC 생성", "유스케이스 만들어줘"
- "Use Case 작성", "유즈케이스 정의해줘", "시나리오 작성", "UC 시나리오"
- "유즈케이스 도출", "유즈케이스 문서 만들어줘"
- FR 목록이나 요구사항 문서를 주며 "유즈케이스로 만들어줘"라고 할 때

## 입력

- **필수**: 요구사항 정의서 파일 또는 FR 목록 (파일 또는 텍스트 직접 입력)
- **선택**: 서비스 카탈로그(SC-NNN), 액터 목록, 설계 기초 추출 문서(`ai-dlc-design-extract` 산출물)

## 분석 절차

1. **FR·SC 수집**: `Read`로 요구사항 파일 읽기, `Grep`으로 `FR-\d+` 패턴 추출
2. **액터 도출**: FR의 주어·권한 정보에서 액터 목록 생성 (일반사용자, 관리자, 시스템 등)
3. **UC 도출**: FR을 그룹핑하여 UC 후보 생성
   - 유사 FR 묶기 (같은 기능 도메인)
   - CRUD 패턴 → 조회/등록/수정/삭제 UC 분리
   - 비즈니스 프로세스 흐름 기반 UC 식별
4. **UC-NNN 채번** (001부터, SC별 그룹 내 순번)
5. **유즈케이스 상세 작성**:
   - 기본 흐름 (주요 성공 시나리오, 번호가 매겨진 단계)
   - 대안 흐름 (정상 범위 내 분기)
   - 예외 흐름 (오류·실패 케이스, FR 내 예외 처리 참조)
6. **FR-UC 커버리지 확인**: 미연계 FR 있으면 UC 추가 또는 보고
7. **Mermaid 유즈케이스 다이어그램** 생성 (액터별 UC 연결)
8. **`template.md` 기반 유즈케이스 문서 생성**

## UC 작성 원칙

- UC명은 동사+목적어 형식: `회원 로그인`, `주문 등록`, `재고 조회`
- 기본 흐름은 3~7단계가 적정 (너무 길면 서브 UC 분리 고려)
- 예외 흐름은 반드시 1개 이상 포함 (로그인 실패, 입력 오류 등)
- FR-NNN 연계 명시로 추적성 확보

## 산출물 포맷

파일명: `유즈케이스_{사업명}_{YYYYMMDD}.md`

`${CLAUDE_SKILL_DIR}/template.md` 골격 사용:

1. **액터 목록**
2. **유즈케이스 목록** (UC-NNN, FR 연계)
3. **유즈케이스 상세** (기본/대안/예외 흐름)
4. **유즈케이스 다이어그램** (Mermaid)
5. **FR-UC 커버리지 매핑**

## 엣지 케이스

- **FR 50개 초과**: 서비스 카탈로그(SC) 기준으로 그룹 분리 후 순차 작성
- **FR 목록 미제공**: 설계 기초 추출 문서의 UC 후보를 기반으로 시작
- **CRUD 외 복잡 UC**: 비즈니스 프로세스 흐름을 우선하되 상세 흐름은 3단계까지만 전개 후 서브 UC 분리
