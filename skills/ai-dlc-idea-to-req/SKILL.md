# AI-DLC 아이디어 → 요구사항 변환 (브리지)

> 아이디어정의서·사용자스토리맵·MVP범위정의서를 읽어
> `ai-dlc-requirements` 출력과 **동일한 포맷**의 요구사항 정의서(FR-NNN)를 생성한다.
> 이 산출물은 바로 `ai-dlc-service-catalog` → `ai-dlc-usecase-create`로 연결된다.

## 트리거

- "요구사항으로 변환해줘", "요구사항 정의서로 만들어줘"
- "AI-DLC로 이어서 진행해줘", "다음 단계로 넘어가줘"
- "FR로 변환해줘", "FR-NNN 만들어줘"
- "요구사항 뽑아줘", "기능 요구사항 정의서 만들어줘"

## 입력

### 필수 (1개 이상)
- `아이디어정의서_*.md` (자동 탐색)
- `사용자스토리맵_*.md` (자동 탐색)
- `MVP범위정의서_*.md` (자동 탐색)

### 선택
- `페르소나_*.md` (액터 추출 보완용)

## 처리 절차

1. **산출물 탐색 및 읽기**
   - `Glob("아이디어정의서_*.md")`, `Glob("사용자스토리맵_*.md")`, `Glob("MVP범위정의서_*.md")`, `Glob("페르소나_*.md")` → 있는 파일 모두 `Read`

2. **사업 기본 정보 추출**
   - 사업명: 아이디어정의서 제목 또는 도메인 기반
   - 사업목적·추진배경: 아이디어정의서 "핵심 문제 정의"에서 추출
   - 기술스택: 아이디어정의서 또는 도메인 기반 추론 (프론트·백엔드·DB)

3. **기능 요구사항(FR-NNN) 변환**
   - MVP Must/Should US 항목 → FR (기능 요구사항)
   - US 스토리 → FR 요구사항명 + 설명 변환:
     ```
     US: "관리자로서, 직원 출퇴근을 확인하기 위해 근태 현황을 조회하고 싶다"
     →  FR-001 | 근태 현황 조회 | 관리자가 직원별 출퇴근 현황을 조회한다 | 상 | -
     ```
   - FR-NNN 채번 (001부터 순차)
   - 중요도: Must → 상, Should → 중, Could → 하

4. **비기능 요구사항 추출**
   - 아이디어정의서·US에서 성능·보안·제약 키워드 탐색
   - PR (성능): "빠르게", "실시간", "대용량" 키워드
   - SR (보안): "로그인", "권한", "암호화", "인증" 키워드
   - CR (제약): "법규", "모바일 전용", "기존 시스템 연동" 키워드
   - 키워드 없으면 기본 PR/SR 최소 1건씩 생성

5. **액터 추출** (페르소나 → 요구사항 주체)
   - 페르소나 PS-NNN → FR의 주체(관리자, 사용자, 시스템)

6. **US-NNN ↔ FR-NNN 매핑 테이블 추가** (추적성 확보)
   ```
   | US-NNN | FR-NNN | 비고 |
   ```

7. **`ai-dlc-requirements`의 `template.md` 읽어 동일 포맷으로 생성**
   - `${CLAUDE_SKILL_DIR}/../ai-dlc-requirements/template.md` 참조

## 산출물

파일명: `요구사항정의서_{사업명}_{YYYYMMDD}.md`
- **포맷**: `ai-dlc-requirements` 출력과 완전 동일
- **추가 섹션**: 문서 하단에 `## 추적성 매핑 (US → FR)` 섹션 추가
- 출력 시 절대 경로 + FR/PR/SR/CR 건수 + 다음 단계 안내

## 다음 단계 안내

생성 후 기존 AI-DLC 파이프라인으로 바로 연결:
```
→ "서비스 카탈로그 만들어줘"  (ai-dlc-service-catalog)
→ "유즈케이스 만들어줘"       (ai-dlc-usecase-create)
```

## 엣지 케이스

- **아이디어정의서만 있는 경우**: 기능 아이디어 목록에서 직접 FR 추출
- **FR이 5개 미만**: 도메인 기반 기본 CRUD FR 추가 제안
- **기술스택 불명확**: "미정"으로 기입하고 "ai-dlc-requirements에서 확정 권장" 주석
