# AI-DLC 산출물 간 일관성 검증

> 개별 validate 스킬이 단일 산출물을 검증하는 것과 달리,  
> 이 스킬은 **여러 산출물 간 교차 일관성**을 통합 검증한다.  
> 여러 revise 후 전체 설계가 여전히 일관된지 확인하는 최종 품질 게이트.

공통 출력 정책: `${CLAUDE_SKILL_DIR}/../ai-dlc-common/references/output-policy.md` 참조.

## 트리거

- "산출물 일관성 검증", "설계 일관성 확인"
- "변경 후 전체 검증", "전체 산출물 크로스체크"
- "설계서 간 일관성", "UC와 API 일치 확인"
- 여러 revise 완료 후 최종 검증을 요청할 때

## 입력

### 필수
- 검증 대상 산출물 (@파일 참조 또는 `설계산출물/` 디렉터리 지정)
- 최소 2개 이상의 산출물 (단일 산출물은 해당 validate 스킬 사용)

### 선택
- CR-NNN (해당 CR 변경 범위만 집중 검증)
- 검증 범위 지정 (예: "UC↔API만 확인", "API↔화면정의서만 확인")

## 처리 절차

1. **검증 대상 산출물 수집**
   - @파일 지정된 경우: 해당 파일 읽기
   - 디렉터리 지정된 경우: `설계산출물/`에서 현행 버전 자동 탐색
   - 현행 버전: 동일 유형에서 날짜가 가장 최신인 파일

2. **ID 교차 참조 검증**
   - UC-NNN 목록 → API operationId 매핑 확인
   - SCR-NNN 목록 → 화면정의서 SCR 섹션 존재 확인
   - API 엔드포인트 → 화면정의서 이벤트→API 참조 일치 확인
   - FR-NNN → UC-NNN 연결 누락 검사

3. **필드/파라미터 일관성 검증**
   - API 응답 스키마 필드명 ↔ 화면정의서 표시 항목명
   - API 요청 파라미터 ↔ 화면정의서 입력 필드
   - DB 테이블 컬럼명 ↔ API 스키마 필드명 (스네이크케이스↔카멜케이스 변환 허용)

4. **누락 및 고아(orphan) 항목 감지**
   - FR 있는데 UC 없음 → 미구현 요구사항
   - UC 있는데 SCR 없음 → 화면 누락
   - API 있는데 화면정의서 참조 없음 → 미사용 API 또는 문서 누락

5. **CI-NNN 이슈 채번 및 심각도 분류**
   - 高: ID 참조 오류 (존재하지 않는 UC-NNN 참조)
   - 中: 필드명 불일치 (API ↔ 화면정의서)
   - 低: 누락 주석, 설명 불일치 (스펙은 일치하나 설명문 차이)

6. **판정**
   - **일관성 확인**: 高심각도 이슈 0개, CI-NNN 합계 3개 이하
   - **부분 불일치 (조건부 승인)**: 高심각도 0개, CI-NNN 10개 이하
   - **재검토 필요**: 高심각도 1개 이상 또는 CI-NNN 11개 이상

## 엣지 케이스

- **산출물 1개만 제공**: "단일 산출물은 /ai-dlc-xxx-validate 스킬을 사용하세요" 안내
- **설계산출물/ 없음**: 경로 재지정 요청
- **버전이 다른 파일 혼재**: 가장 최신 날짜 파일만 사용하고 "이전 버전 파일 무시" 명시
- **프레임워크 비의존적 산출물 (UC, API)**: 기술 스택 무관하게 검증 수행
