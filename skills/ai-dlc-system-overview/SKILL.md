# AI-DLC 시스템 개요서

> 프로젝트의 모든 AI-DLC 설계 산출물을 읽어 시스템 목적·아키텍처·주요 기능·기술 스택을
> 한 문서로 통합 요약한 `시스템개요서_*.md`를 생성한다.
> 이 문서는 프로젝트를 처음 접하는 누구든 시스템 전체 맥락을 이해하는 단일 진입점이 된다.

## 트리거

- "시스템 개요서 만들어줘", "시스템 전체 요약 문서 만들어줘"
- "프로젝트 개요서 작성해줘", "시스템 소개 문서 만들어줘"
- "인수인계 개요서 작성해줘", "시스템 요약 문서 만들어줘"
- "전체 시스템 정리해줘", "시스템 아키텍처 정리해줘"

## 입력

### 자동 탐색 (있는 파일만 활용)
- `요구사항정의서_*.md` — 사업목적, 기술스택, FR 건수
- `유즈케이스_*.md` — 액터 목록, UC 목록
- `화면목록_*.md` 또는 `화면정의서_*.md` — 화면 목록
- `openapi_*.yaml` 또는 `API설계서_*.md` — API 엔드포인트 목록
- `데이터설계서_*.md` — 테이블 목록

### 선택 (보완용)
- `서비스분류_*.md` — 서비스 그룹 구조
- `클래스설계서_*.md` — 시스템 내부 구조
- `비즈니스규칙_*.md` — 주요 규칙 요약

## 처리 절차

1. **산출물 탐색 및 읽기**
   - Glob 패턴으로 각 산출물 탐색 → Read
   - 없는 파일은 해당 섹션 "(정보 없음)" 처리

2. **핵심 정보 추출**
   - 요구사항정의서 1절 → 사업목적·추진배경 (2~3문장)
   - 요구사항정의서 3절 기술스택 표 → 기술스택 표
   - 요구사항정의서 2절 FR 건수 → 기능 규모
   - 유즈케이스 → 액터 목록 + UC 목록 (이름·설명·액터)
   - 화면목록/화면정의서 → SCR-NNN, 화면명, URL 목록
   - API설계서 YAML → paths 추출 → Method·Endpoint·summary 목록
   - 데이터설계서 → 테이블명·설명 목록

3. **시스템 아키텍처 ASCII 다이어그램 생성**
   - 기술스택 기반으로 계층 구성:
     ```
     [사용자 브라우저]
           │ HTTP/HTTPS
     [Frontend: React/Vue/Next.js]
           │ REST API
     [Backend: Spring Boot]
           │ JDBC/MyBatis
     [Database: PostgreSQL/MySQL]
     ```

4. **template.md 기반 파일 생성**

## 산출물

파일명: `시스템개요서_{사업명}_{YYYYMMDD}.md`
- 출력 시 절대 경로 + 포함된 섹션 목록 요약

## 엣지 케이스

- **요구사항정의서만 있는 경우**: FR 목록에서 기능 섹션 추론, 나머지 섹션 "설계 문서 미생성" 표시
- **API설계서가 YAML 형식**: paths 키에서 엔드포인트·메서드·summary 직접 추출
- **화면목록과 화면정의서 둘 다 있는 경우**: 화면정의서 우선 사용 (더 상세)
