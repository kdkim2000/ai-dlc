# AI-DLC MVP 범위 정의

> 사용자 스토리맵 또는 기능 목록을 MoSCoW 기법으로 분류하고
> 가치·복잡도 매트릭스를 통해 MVP(v1.0) 구성과 릴리즈 로드맵을 생성한다.
> 이 산출물은 `ai-dlc-idea-to-req`의 핵심 입력이 된다.

## 트리거

- "MVP 정의해줘", "MVP 범위 정해줘"
- "최소 기능 정의해줘", "최소 기능 제품 정의"
- "어떤 것부터 만들어야 하나", "1차 오픈 범위 정해줘"
- "우선순위 정해줘", "기능 우선순위 분류"
- "MoSCoW 분석해줘", "릴리즈 계획 세워줘"

## 입력

### 필수 (택일)
- `사용자스토리맵_*.md` (자동 탐색)
- `아이디어정의서_*.md` (자동 탐색)
- 자연어 기능 목록

### 선택
- `페르소나_*.md` (가치 평가 기준 보완용)

## 처리 절차

1. **산출물 탐색**
   - `Glob("사용자스토리맵_*.md")` → `Read`
   - `Glob("아이디어정의서_*.md")` → `Read`
   - US 목록 또는 기능 아이디어 목록 수집

2. **MoSCoW 분류** (기준 적용)
   - **Must Have**: 없으면 서비스 핵심 목적 불가 (예: 로그인, 핵심 CRUD)
   - **Should Have**: 중요하지만 첫 릴리즈에서 우회 가능 (예: 알림, 검색 필터)
   - **Could Have**: 있으면 좋지만 없어도 운영 가능 (예: 다크모드, 내보내기)
   - **Won't Have (v1)**: 이번 버전 제외, 다음 버전으로 이연 (예: 모바일 앱, AI 추천)

3. **가치 vs 복잡도 평가** (각 기능)
   - 가치(Value): 사용자/비즈니스 임팩트 H/M/L
   - 복잡도(Complexity): 개발 난이도·공수 H/M/L
   - Quick Win (고가치·저복잡도) 식별 → MVP 우선 포함

4. **MVP 구성 결정**
   - Must 전체 + Quick Win Should 포함
   - 총 기능 수가 MVP에 적절한지 검토 (권장: 10~20개 FR 수준)

5. **릴리즈 로드맵 초안 작성**
   - v1.0 MVP, v1.1, v2.0 구성

6. **`template.md` 기반 파일 생성**

## 산출물

파일명: `MVP범위정의서_{사업명}_{YYYYMMDD}.md`
- 출력 시 절대 경로 + Must/Should/Could/Won't 건수 표시

## 엣지 케이스

- **US 없이 기능 목록만 있는 경우**: 기능 항목으로 직접 MoSCoW 적용
- **Must가 너무 많은 경우**: "없으면 서비스 불가"인지 재검토 후 일부 Should로 재분류
- **릴리즈 일정 미정**: "(미정)" 기입 후 "ai-dlc-requirements에서 확정 권장" 주석 추가
