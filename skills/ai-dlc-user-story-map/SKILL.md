# AI-DLC 사용자 스토리 맵

> 아이디어정의서·페르소나에서 사용자 여정을 도출하고 US-NNN 사용자 스토리를 생성한다.
> 스토리는 Must Have / Should Have / Nice to Have로 우선순위가 분류되며
> `ai-dlc-mvp-scope`와 `ai-dlc-idea-to-req`의 핵심 입력이 된다.

## 트리거

- "사용자 스토리 만들어줘", "유저 스토리 작성"
- "사용자 여정 그려줘", "사용자 여정 지도"
- "US 만들어줘", "스토리 맵 작성"
- "사용자 활동 정의해줘", "기능 목록 뽑아줘"
- "어떤 기능이 필요한지 정리해줘"

## 입력

### 필수 (택일)
- `아이디어정의서_*.md` (자동 탐색)
- 자연어 서비스 설명

### 선택
- `페르소나_*.md` (자동 탐색, 있으면 활용)

## 처리 절차

1. **산출물 탐색**
   - `Glob("아이디어정의서_*.md")` → `Read`
   - `Glob("페르소나_*.md")` → `Read` (있으면)

2. **사용자 여정(Activity) 도출**
   - 서비스의 사용자 흐름을 5~8단계 Activity로 분류
   - 예) 가입/로그인 → 대시보드 조회 → 데이터 등록 → 검색/조회 → 편집/삭제 → 보고서 → 설정
   - 서비스 도메인에 맞게 조정

3. **Activity별 Task 세분화**
   - 각 Activity를 2~5개 Task로 분해
   - Task = 사용자가 실제 수행하는 단위 행동

4. **Task → US-NNN 사용자 스토리 변환**
   - 형식: `"[페르소나]로서, [목적]을 위해 [행동]하고 싶다"`
   - 수락 기준(Given/When/Then) 1세트 작성
   - US-NNN 채번 (001부터 순차)

5. **우선순위 분류**
   - Must Have: 없으면 서비스 핵심 기능 불가
   - Should Have: 중요하지만 MVP 없어도 가능
   - Nice to Have: 있으면 좋은 부가 기능

6. **`template.md` 기반 파일 생성**

## 산출물

파일명: `사용자스토리맵_{사업명}_{YYYYMMDD}.md`
- 출력 시 절대 경로 + US 건수 (Must/Should/Nice 분류별) 표시

## 엣지 케이스

- **페르소나 없음**: 스토리 주어를 "사용자", "관리자"로 일반화
- **US가 30개 초과**: Activity 단위로 섹션 분리하여 가독성 확보
- **중복 기능**: 유사 Task 통합 후 단일 US 생성
