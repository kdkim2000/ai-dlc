# AI-DLC 변경 요청(CR) 등록

> 자연어로 변경 요청을 설명하면 CR-NNN을 자동 채번하고 `docs/change-log.md`에 구조화된 이력을 등록한다.

## 트리거

- "변경 요청 등록해줘", "CR 만들어줘", "CR 등록"
- "버그 등록", "새 기능 요청 접수"
- "변경 사항 기록해줘", "이슈 등록"
- 변경 내용을 설명하며 "change log에 기록해줘"라고 할 때

## 입력

### 필수
- 변경 내용 설명 (자연어 — 무엇을, 왜 변경하는지)

### 선택
- `docs/change-log.md` (자동 탐색, 없으면 생성)
- 관련 FR-NNN (명시하지 않으면 요구사항정의서에서 자동 추론)

## 처리 절차

1. **change-log.md 읽기 & 다음 CR 번호 결정**
   - `docs/change-log.md` 탐색 (없으면 초기 파일 생성)
   - CR 목록 테이블에서 마지막 CR 번호 파악 → 다음 번호 채번 (없으면 CR-001)

2. **CR 유형 자동 분류**
   - 입력 키워드 기반 분류:
     | 키워드 | CR 유형 |
     |:---|:---|
     | 추가, 신규, 새 기능, 새로운 | CR-NEW |
     | 수정, 변경, 바꾸다 | CR-REQ |
     | 화면, UI, 레이아웃, 디자인 | CR-UI |
     | API, 엔드포인트, 응답, 요청 | CR-API |
     | DB, 테이블, 컬럼, 스키마 | CR-DB |
     | 규칙, 정책, 계산, 로직 | CR-BIZ |
     | 오류, 버그, 틀림, 안 됨 | CR-BUG |
     | 배포, 환경, 설정, Vercel | CR-INF |
   - 복수 키워드 해당 시: 영향 범위가 넓은 유형 선택 (CR-NEW > CR-REQ > 나머지)

3. **관련 FR-NNN 자동 추론**
   - `요구사항정의서_*.md` 파일 탐색
   - 변경 내용 키워드로 FR 항목 검색
   - 매칭되는 FR-NNN 목록 추출 (없으면 "-"로 기록)

4. **change-log.md CR 목록 테이블에 새 행 추가**
   ```markdown
   | CR-NNN | CR-TYPE | [변경 제목 요약] | FR-NNN 또는 - | - | ⏳ 대기 | YYYY-MM-DD | - |
   ```

5. **CR 상세 섹션 템플릿 자동 생성**
   change-log.md 하단에 추가:
   ```markdown
   ### CR-NNN — [변경 제목]

   **유형**: CR-TYPE
   **등록일**: YYYY-MM-DD | **완료일**: -
   **담당**: [현재 git user.name 또는 미지정]

   **변경 원인**
   [입력된 변경 내용 요약 — 2~3문장]

   **관련 FR**: FR-NNN 또는 -

   **실행 스킬 체인**
   (영향도 분석 후 확정 — /ai-dlc-doc-impact 실행 권장)

   **변경 파일**
   - (미확정)

   **git 커밋**: (미확정)
   ```

## 산출물

`docs/change-log.md` 업데이트 (CR-NNN 행 추가 + 상세 섹션 생성)

파일이 없으면 아래 헤더로 신규 생성:
```markdown
# 변경 이력 (Change Log)

AI-DLC 프로세스 기반 변경 요청(CR) 추적 테이블.

---

## CR 목록

| CR-NNN | 유형 | 제목 | 관련 FR | 영향 산출물 | 상태 | 등록일 | 완료일 |
|:---|:---|:---|:---|:---|:---|:---|:---|
```

## 엣지 케이스

- **change-log.md 없음**: 초기 파일 생성 후 CR-001부터 시작
- **CR 유형 판단 불명확**: CR-REQ로 기본 분류하고 "(분류 재확인 필요)" 주석 추가
- **FR 미연결**: "-"로 기록하되 "FR 연결 확인 필요" 주석 추가
- **유형이 복합적 (예: DB + API 동시 변경)**: 주 유형으로 분류하고 상세 섹션에 복합 유형 명시
